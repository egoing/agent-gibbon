## 조사와 중복 확인

#137은 화면 캡처 접근 확인 실패·설정 이동·재시도·개발 앱 식별을 직접 다룬다. #41은 입력 관찰과 복수 인스턴스의 경계 검증이며 화면 캡처 복구와 별개다. #25는 캡처 성능, #35는 숨김 기능의 상위 추적이다. 네 이슈의 댓글은 조회 시 모두 0개였다. 저장소 docs/design 전체 및 권한 관련 이슈 검색에서 해당 복구 시안을 찾지 못했다. privacy-onboarding은 약관·선택적 진단 전송 동의이며 OS 권한 안내로 재사용하지 않는다. 모든 과거 비공개 첨부나 다른 로컬 작업 사본까지 부재를 증명한 것은 아니다.

## 표면과 사용자 흐름

관리 창의 중립 회색 역할 색상, 본문 13px, 보조 글자 #626262, 표면 #f8f8f8, 조작 경계 #858585를 재사용한다. 시안의 568×396 안내 표면·24px 안쪽 여백·4px 모서리·32px 버튼은 이번 제안 수치다. 메모 툴바 수치를 안내창에 강제하지 않는다. 좁은 화면에서는 본문 스크롤·버튼 줄바꿈을 허용하며 최소 크기는 구현 검증 후 결정한다. 그림은 실제 창 캡처가 아닌 1240×1160 상태 비교 보드다.

| 상태/입력 | 안내와 다음 행동 |
|---|---|
| 접근 검사 결과 false | ‘접근을 확인할 수 없습니다’로 안내하며 사용자의 명시적 거부로 단정하지 않는다. 설정 열기·이미 허용했어요·나중에를 제공한다. |
| 설정 열기 | 사용자 클릭 때만 OS 설정 이동을 시도한다. 권한을 자동으로 켜지 않는다. 반환 후 02에서 다시 확인한다. 설정을 열었다는 사실로 권한 획득을 판정하지 않는다. |
| 설정 이동 실패 | ‘설정을 열지 못했습니다’를 같은 표면에 표시하고 화면에 적힌 수동 경로를 유지한다. 깊은 링크 지원·해당 항목 직접 이동 성공은 아직 검증하지 않았다. |
| 이미 허용했어요 | 현재 앱과 설정 목록의 항목 일치 여부·개발 재빌드 가능성을 안내한다. 원인을 확정하거나 다른 앱 권한 삭제·TCC 초기화를 권하지 않는다. |
| 다시 확인 | 상태 조회만 수행하는 03으로 전환하고 중복 버튼을 비활성화한다. 자동 캡처나 권한 요청 반복을 하지 않는다. |
| 접근 확인 성공 | 같은 표면에 ‘화면 캡처 접근을 확인했습니다’와 ‘캡처 시작’·‘나중에’를 제공한다. 사용자가 캡처 시작을 누를 때만 새 캡처를 시도한다. 접근 확인 성공이 실제 캡처 성공을 보장하지는 않는다. |
| 재확인 false | 02를 유지하며 ‘아직 접근을 확인할 수 없습니다’를 표시한다. OS 재실행 안내가 있었는지 확인하도록 돕는다. |
| 조회 실패·시간 초과 | ‘확인하지 못했습니다’와 다시 확인을 제공한다. false 결과나 거부로 바꾸지 않는다. |
| 접근 검사를 통과한 후 일반 캡처 오류 | 04에서 작업 단계·오류 코드를 안내하고 캡처 다시 시도를 제공한다. 권한 재허용을 해결책으로 단정하지 않는다. |
| OS에서 종료·재실행 요청 | 작업 저장 후 수동 재실행 방법을 안내한다. 자동 종료·재시작 버튼은 이번 제안에 포함하지 않는다. 실행 중 PTY 보존을 보장할 수 없으므로 강제 재시작하지 않는다. |
| 나중에·네이티브 닫기·Escape | 현재 캡처 시도만 취소하고 안내를 닫는다. 다음 사용자의 캡처 요청에서 다시 검사한다. 시간 기반 반복 알림을 만들지 않는다. |

캡처 임시 overlay·버퍼 정리 후 별도 비포커스 안내를 표시하고 기존 작업의 키보드 초점·메모 위치·크기·숨김을 유지하는 것이 제안이다. 사용자가 안내를 직접 선택했을 때만 버튼 조작을 위해 활성화한다. 이미 표시 중이면 같은 안내를 갱신한다. 설정 앱을 여는 명시적 조작에 따른 전환과 배경 안내의 포커스 보존을 구분한다. 실제 비활성 창의 버튼 첫 클릭과 키보드 진입은 후속 네이티브 검증 대상이다.

화면 순서대로 Tab 이동, visible focus, 진행에는 status, 오류에는 alert를 제공한다. 동일 오류를 반복 낭독하지 않는다. 현재 앱 이름·설치/개발 구분·버전·실행 경로는 기본 노출하고 PID·인스턴스·서명 확인 결과는 실행 정보에 담는다. 시안의 축약 경로는 펼치면 전체를 선택/복사할 수 있게 하되 자동 전송·로그 저장하지 않는다. 이 정보가 OS 설정 항목과 자동 대조됐다는 의미는 아니다. 확인되지 않은 서명은 ‘미확인’으로 표시한다. 설치본에는 가짜 개발 인스턴스를 표시하지 않는다.

Orca·Codex 등 외부 조작 도구의 손쉬운 사용 권한과 Agent Gibbon 자신의 화면 캡처 권한을 혼동하지 않는다. Agent Gibbon의 입력 관찰 권한(#41) 또한 별도 진단이다. 해당 화면에서 불필요한 손쉬운 사용·전체 디스크·관리자 권한을 요구하지 않는다. 약관 수락과 진단 전송 동의는 변경하지 않는다.

## Apple 공식 근거와 한계

- [Apple: 화면 및 시스템 오디오 기록 접근 제어](https://support.apple.com/ko-kr/guide/mac-help/mchld6aa7d23/mac): 시스템 설정 → 개인정보 보호 및 보안 → **화면 및 시스템 오디오 녹음**에서 앱별 허용을 조절한다. 제목의 ‘기록’과 실제 항목의 ‘녹음’을 구분했다. OS 버전·언어별 명칭은 후속 검증하며 그림은 한국어 예시다. 화면 캡처 안내가 시스템 오디오 녹음 기능 구현을 뜻하지 않는다.
- [Apple DTS: ad-hoc 서명과 재빌드](https://developer.apple.com/forums/thread/819406): ad-hoc 재빌드가 새 앱으로 취급될 수 있다는 설명의 근거다. 현재 Agent Gibbon 장애에서 서명 변경이 확정 원인이라는 뜻은 아니다.

## 추가 제안: 권한 안내 및 설정

[권한 개요·보조 안내 SVG](permission-settings-20261114.svg) · [PNG](permission-settings-20261114.png).

사용자가 제공한 ChatGPT Computer Use 권한 개요와 설정 위 보조 안내 두 이미지를 읽기 전용으로 확인하고, **필요 이유 → 현재 확인 상태 → 명시적 설정 진입 → 허용 대상 앱 식별 → 재확인** 순서를 준용했다. 기존 4상태 시안은 실패 진단의 상세 흐름으로 유지한다. 사용자의 후속 요청 “첨부한 이미지와 같은 디자인으로 똑같이 따라해줘”에 따라 큰 카드·반투명 재질 표현·큰 중앙 제목·앱 아이콘·권한별 아이콘/상태·캡슐형 허용 버튼·화살표와 드래그 행을 참고 이미지 구성에 맞게 다시 그렸다. 추가 시안은 기존 13px/4px 일반 관리 창 규칙의 예외 제안이며 제품 전체 스타일 변경을 뜻하지 않는다. 1200×876 개요 표면, 160px 높이·48px 모서리 카드, 49px 제목·26px 본문은 참고 이미지에 맞춘 제안 수치다. 앱 이름·아이콘과 문구는 Gibbon에 맞췄다. SVG의 그라데이션은 유리 재질의 시각 모사이며 실제 OS 배경 blur 구현 증거가 아니다.

- 최초 허용과 이후 재설정 모두 개요 화면으로 진입할 수 있다. 초기 설치 때 모든 권한을 일괄 요청하지 않고 기능 사용 시 해당 항목을 제시한다. 화면 캡처와 Gibbon 입력 관찰은 별도 상태이며, 조회하지 않은 항목은 ‘미확인’, 조회 중은 ‘확인 중’, 성공은 ‘확인됨’, 시간 초과/조회 실패는 ‘확인하지 못함’으로 표시한다. 그림의 입력 관찰 확인됨은 가상 예시이며 실측이 아니다. #41 범위의 실제 조회 가능성·권한 종류는 별도 검증한다.
- 시스템 설정을 열었을 때 현재 앱 아이콘·이름·설치/개발 구분·실행 경로를 담은 작은 보조 안내를 제안한다. 위쪽 화살표는 설정 목록을 가리키는 개념 표현이다. 실제 좌표 추적·배치·설정 위 유지·Spaces·다중 화면 동작은 미검증이며, 다른 창을 이동하거나 Gibbon의 숨긴 메모를 복원하지 않는다. 뒤로 가기는 보조 안내만 닫고 권한 개요로 돌아가며 OS 설정을 종료하지 않는다.
- 설치 앱 번들을 사용자가 드래그해 추가하는 방식은 **선택 제안**이다. 드래그 데이터·OS 수락·정확한 권한 항목 지원을 아직 검증하지 않았다. Apple 공식 안내로 확인한 추가(+)와 앱 선택의 수동 절차를 기본 대안으로 유지한다. 개발 바이너리가 .app이 아닌 경우 드래그 가능한 앱처럼 가장하지 않고 경로와 수동 확인 안내를 제공한다. 실제 현재 앱의 아이콘/경로 조회가 실패하면 기본 아이콘과 미확인 상태를 사용한다.
- 사용자 관찰에서는 화면 녹음 권한을 끄고 캡처를 재시도했을 때 도구에 약 30초 후 timeout이 반환됐지만 별도의 권한 안내가 화면에 보였다. 이는 ChatGPT Computer Use 사용 중 관찰이며 Gibbon의 재현 결과가 아니다. API/도구 결과와 사용자에게 표시되는 안내의 상태를 독립적으로 다루며, timeout만으로 권한 거부·안내 미표시·안내 종료를 단정하지 않는다. 구현 시 요청 결과·권한 조회·안내 표시 상태를 각각 검증한다.

추가 검증: 저장소의 기존 앱 아이콘을 SVG에 내장했다. rsvg-convert 2.62.3으로 PNG 1354×1430을 생성하고 실제 이미지 도구로 한글·아이콘·버튼·설정 보조 안내의 잘림/겹침이 없음을 확인했다. XML·이미지 크기·상대 링크·공백 검사를 수행했다. 드래그·상태 조회·설정 진입·실제 OS 권한·포커스·반응형 동작은 미검증이다. Conf 2 / Risk Low를 유지한다. 최종 시안 변경은 계속 로컬 미커밋이며 구현 승인을 뜻하지 않는다.

사용자 외형 재현 요청 반영 후 1354×1430 PNG를 다시 열어 카드·한글·아이콘·보조 안내 배치를 육안 확인했다. 기존 상세 복구 시안은 유지한다. OS 지원 검증 전 드래그 문구는 승인 전 시안 안의 제안이며 실제 기능 약속이 아니다.
