# 메모 여백과 오버레이 스크롤바 제안

상태: 사용자 승인 대기. 앱 구현·확정 디자인 기준 변경 없음.

[기존 디자인 시스템](../../design-system.md)을 참조한 독립 제안이다. 기존 툴바 30px 규칙을 22px로 바꾸는 내용은 아직 합의되지 않았다. 첨부 초록 선은 제거 대상 표시로 해석했다.

## 시안

[PNG](overlay-scrollbar-20261113.png) · [SVG](overlay-scrollbar-20261113.svg)

첨부 메모의 약 600:582 비율을 300×291 논리 좌표로 재구성하고 1.6배 확대했다. 정적 예상도이며 실앱 캡처가 아니다. 동일한 긴 문서를 기본·표시 상태로 비교한다. 초록 주석은 시안에 넣지 않았다.

- 버튼 슬롯 24×22px, 아이콘 12px를 유지하고 툴바 행만 30→22px로 줄인다. 툴바와 본문 사이 추가 상단 패딩은 0으로 제안한다. 제목 자체의 글꼴 ascender 여유는 남는다.
- 스크롤바 전용 열과 트랙 배경을 없앤다. 좌우 기본 3px는 글자와 창 모서리의 최소 간격으로 유지한다. thumb는 우측 2px 위치에 폭 3px로 겹친다. 외곽 활성 프레임은 기존 규칙을 유지하며 이번 시안은 비활성 표면이다.
- 긴 메모는 처음 표시할 때 짧게 thumb를 보여 스크롤 가능성을 알린다. 이후 스크롤·우측 가장자리 접근·키보드 초점 동안 표시하고 잠시 후 숨긴다. 드래그 중에는 유지한다. 시간 수치는 구현 전 제안 대상으로 남긴다.
- thumb 길이와 위치는 실제 scrollHeight/clientHeight/scrollTop에 연동한다. 짧은 문서에는 표시하지 않는다. 시안은 아래에 더 긴 내용이 있는 문서다.
- 드래그 시에만 thumb 주변의 투명 hit area를 약 12px로 확대하는 방안을 검토한다. 평소 본문 선택·링크·메모 이동은 가로채지 않는다. 우측 끝 글자와 hit area가 겹치면 글자 조작을 우선하고 thumb 직접 접근 또는 키보드를 제공해야 한다. 승인 후 좁은 창·긴 줄·표에서 구체적 충돌 검증이 필요하다.
- 기존 네이티브 스크롤 컨테이너를 유지해 휠·트랙패드 관성과 키보드 스크롤을 사용한다. 키보드 포커스와 방향키·PageUp/Down·Home/End, 스크린리더의 본문 탐색을 검증한다. 조작 가능한 커스텀 scrollbar에는 접근성 이름·현재값·제어 대상·키보드 동작이 필요하다. 장식용 복제라면 접근성 트리에서 숨긴다.
- 스크롤바 상시 표시 선호·고대비 환경에는 지속 표시/네이티브 대체를 제공하고 reduced-motion에서는 fade를 생략하는 방안을 제안한다. OS 선호 감지 가능 범위는 승인 후 플랫폼별 확인이 필요하다.

## 읽기 전용 조사와 검증

작업 루트: `/Users/egoinglee/.codex/worktrees/02ec/agent-gibbon`.

`ui/style.css`의 `#viewport`는 flex 본문이며 `overflow: auto`, 3px padding을 사용한다. 툴바 최종 규칙은 행 30px·버튼 22px다. 따라서 본문 확장과 오버레이 표시를 프론트엔드에서 구성할 여지는 확인했다. 네이티브 스크롤바 숨김의 WKWebView/Windows 호환성과 실제 입력 동작은 이번에 검증하지 않았다. 외부 WebView·터미널·편집기·코드 블록까지 일괄 적용하는 범위는 이번 승인 대상에 포함하지 않는다.

Node v26.0.0, Python 3.11.3, 로컬 rsvg-convert로 SVG를 PNG 렌더링하고 육안 확인했다. 앱 빌드·실행·GUI 조작·커밋·푸시·병합을 수행하지 않았다. 기존 미커밋 파일과 디자인 시스템 원문은 보존했다. 제안 파일 세 개만 새로 작성했다.
