# 세 보조키와 포인터 방향으로 전체 메모 정리하기 — 조사 계획

기준: main 91b1751, 2026-11-14. 조사·사용성 평가 전용이며 제품 구현·GUI 조작·사용자 창 변경을 하지 않는다.

사용자 원문: “cmd+opt+cmd를 누를 때 기본동작을 마우스포인트중심으로 아래로움직이면접기(이미접혀있다면무조건펼치기),오른쪽으로이동하면모든메모창오른쪽재정렬(이미수정한것포함,크기도조정),위로움직이면가운데에생성순서대로보기좋게정렬(수정한것포함크기조정). 위와같이하면어떤것같아”

단축키 오기 여부는 팀장이 확인 중이다. 잠정 해석은 기존 Control Option Command를 누른 상태의 포인터 방향 이동이다. ‘접기’는 사용자 확인에 따라 현재 전체 숨김·복원(stash) 방식으로 확정한다. 창별 fold는 아니다. 이미 숨김 상태라면 무조건 복원한다.

- [x] 입력·stash·fold·배치·생성 순서·모니터·터미널 크기 변경 근거 확인
- [x] 방향 제스처의 인지성·취소·오작동·복원 정책 평가
- [x] 재사용 범위와 최소 확인 사항, 후속 검증 조건 정리

음성·진행 메모는 팀장이 담당한다. 관계 프로토타입의 숨김 geometry 조사는 별도 작업으로 취급하고 추측 원인을 재사용하지 않는다. 최종 조사 문서는 미커밋으로 남긴다.


## 평가 결론 — 제안이며 확정 규칙 아님

제안은 타당하다. 오른쪽은 주변으로 정리, 위는 중앙에서 전체 검토, 아래는 접기/펼치기로 역할이 구별되고 수동 조정한 메모까지 명시적으로 다시 정리할 수 있다. 특히 자동 배치가 사용자 조정을 보호하는 현재 규칙과, 사용자가 직접 요청한 전체 재정렬을 별도 명령으로 구분하면 목적이 명확하다. 아래는 현재 전체 숨김·복원(stash)으로 사용자 확인되었다. 생성 순서를 현재 열기 순서와 같은 것으로 취급하면 원문 목표가 바뀐다. 아래 평가는 코드 기반 전문가 검토이며 실사용자 시험 결과가 아니다.

### 최소 확인 사항

1. `cmd+opt+cmd`가 기존 Control Option Command를 뜻하는지 팀장의 질문 결과를 따른다.
확정 사항: 아래의 ‘접기’는 현재 전체 숨김·복원(stash)이다. 창별 fold는 아니며 이미 숨긴 상태에서는 무조건 복원한다. 따라서 아래의 fold 대안은 검토에서 제외한다. ‘마우스포인트중심’은 방향 판정의 원점으로 해석하며, 현재 stash의 커서 화면 오른쪽 하단 목적지를 커서 위치 자체로 바꾸는 요구로 확대하지 않는다.

그 밖의 세부 수치를 사용자 질문 목록으로 늘리지 않고 아래 기본안을 검토용으로 제시한다. 모든 메모는 우선 현재 보이는 일반 메모와 stash가 보관 중인 메모를 의미하고, 사용자가 명시적으로 숨기거나 종료한 저장 메모까지 다시 열지 않는 안이다. 웹·터미널까지 포함하는지는 용어 범위를 구현 전 명시해야 한다.

### 동작별 기본안

| 입력 | 제안 동작 | 장점·주의 |
|---|---|---|
| 아래 | 활성 복원 세션이 있으면 그 세션을 반드시 복원, 없으면 대상 전체 접어두기 | 현재의 원위치·크기·기존 개별 fold 복원을 재사용할 수 있다. 복원 중 재입력은 복원 목표를 유지해 ‘무조건 펼침’을 지킨다. 기존 단순 toggle은 반대로 다시 숨길 수 있다. |
| 오른쪽 | 수동 이동·리사이즈·warp한 메모도 포함해 크기를 재산정하고 오른쪽으로 정리 | 기존 제외 표식을 영구 해제하는 것과 이번 명령에서만 무시하는 것은 다르다. 기본안은 이번 명령에만 강제 포함하고 이후 자동 배치의 사용자 의도는 보존한다. |
| 위 | 동일 대상을 생성 순서대로 중앙 묶음에 배열, 크기 재산정 | 오래된 것부터 왼쪽→오른쪽, 위→아래의 행 우선 순서를 제안한다. 현재 아래→위 열 배치를 그대로 중앙으로 옮기는 것은 독서 순서와 다르다. |

위/오른쪽 실행 시 접힌 메모를 자동으로 펼칠지는 원문에 없다. 기본안은 개별 fold를 보존하고 접힌 막대도 정렬하며, 아래로 펼친 뒤 위를 입력하면 전체 내용을 볼 수 있게 한다. stash 중 위/오른쪽은 보관 대상 메모를 펼쳐 해당 목적 배치로 한 번에 옮기는 안이며, 원위치 복원 후 다시 재배치하는 두 단계 애니메이션을 피한다.

### 입력·인지성·실수 방지

- 세 키가 모두 눌린 시점의 포인터를 원점으로 고정한다. 이후 포인터의 상대 이동으로 판정하고, 원점 화면도 고정해 모니터 경계 통과로 목적 화면이 바뀌지 않게 한다.
- 잠정 시험값은 논리 좌표 40px 이동, 주축이 다른 축의 1.5배 이상일 때 아래/오른쪽/위 선택이다. 값은 미검증이다. 대각선과 왼쪽은 미선택이며 잘못된 방향을 억지로 가까운 명령으로 치환하지 않는다.
- 처음 유효 방향을 한 번 잠그고 미리보기로 ‘모두 펼치기/오른쪽 정리/가운데 정리’를 알린다. 키를 **모두 놓을 때** 한 번 실행한다. 임계거리 통과 즉시 창을 옮기면 방향 수정과 취소가 불가능하고 이동 중 반복 실행하기 쉽다. 방향이 잠긴 뒤에는 다른 방향으로 움직여도 재선택하지 않으며 Esc로 취소 후 다시 시작한다.
- Esc는 전체 키 해제까지 취소를 유지한다. 클릭·일반 키·Shift·휠은 현재 혼합 입력 취소를 보존한다. 세 보조키+휠 투명도 조절을 우선하고 배치 명령은 취소해야 한다. Esc가 터미널 등 전면 앱으로 전달되는 문제는 별도 입력 검증 대상이며 현재 전역 관찰이 키를 소비한다고 가정하면 안 된다.
- 임계거리 미만의 무방향 tap은 기존 전체 stash 토글을 유지하는 호환안을 제안한다. 일단 임계거리를 넘었지만 대각선/왼쪽으로 끝난 경우와 Esc 취소에는 tap을 실행하지 않는다. 기존 기능을 기대하며 키를 누른 채 크게 포인터를 옮기던 사용자의 행동은 달라지므로 짧은 안내가 필요하다.
- 아래=접기, 오른쪽=오른쪽은 공간 대응이 좋다. 위=가운데는 방향과 목적지가 달라 발견성이 약하므로 세 키를 누르면 표시하는 작은 방향 안내와 메뉴의 동일 명령을 제안한다. 이는 구현 승인 전 새 UI 제안이다.
- 화면 가장자리에서 밖으로 움직일 공간이 없을 수 있다. 40px 판정만으로 해결되지 않으며 메뉴 대체 동작이 필요하다. 마우스/트랙패드, 느린 이동/빠른 이동·흔들림을 실제 시험하고 임계값을 조정한다.

### 화면·크기·복원 정책

- 커서 원점이 속한 모니터의 작업 영역을 기본 목적지로 제안한다. 다른 모니터의 대상까지 모으는 것은 전체 정리 원문과 양립하지만 사용자의 공간 기억을 바꾸므로 안내에 목적 화면을 드러낸다. 화면 전체 영역으로 모니터를 식별하고 실제 배치는 메뉴바/Dock을 제외한 작업 영역을 쓴다.
- 음수 원점·세로 배열 모니터·혼합 DPI에서 physical/logical 좌표를 일관되게 변환한다. 현재 stash와 layout의 변환 코드가 있다고 혼합 DPI 통과로 인정하지 않는다. 제스처 중 모니터가 사라지면 취소, 실행 직전 사라졌으면 재계획 후 안내하는 안이다.
- 텍스트는 가독성 있는 최소 크기와 내용 높이 상한, 이미지는 원래 비율을 유지한다. 모든 창을 화면에 맞추려고 임의 비율로 찌그러뜨리거나 글자 크기를 줄이지 않는다. 웹 최소 240×160, fold 24px 등 타입별 네이티브 제약을 확인해야 하며 터미널의 네이티브 최소 2×2를 실제 사용 가능한 최소 크기라고 취급하지 않는다.
- 많은 창의 경우 모든 내용을 비겹침·한 화면·최소 크기로 동시에 만족할 수 없다. 3·10·30개와 긴 메모·큰 이미지로 계획을 먼저 계산하고, 수용 불가 시 실행하지 않은 채 이유를 알리는 보수적 기본안을 제안한다. 현재 reflow의 ‘기존 창은 그대로, 새 창만 최소 겹침’ fallback은 전체 재정렬의 성공으로 보고할 수 없다. 다중 화면 확장·겹침·페이지 분할은 후속 선택 사항이다.
- 위/오른쪽은 직전 배치 한 번 되돌리기를 권한다. 위치·크기·표시·fold·자동 배치 제외·모니터·불투명도·warp 기준을 실행 전에 저장하고 원래 포커스를 유지한다. stash snapshot은 임시 가시성 전환이라 일반 배치 undo를 이미 지원하지 않는다. 종료된 창을 부활시키거나 새 창까지 되돌리지 않으며 개별 사용자 조정 이후 해당 창을 덮어쓸지 정책을 명시해야 한다. 터미널 크기 복원은 화면/TUI 출력까지 되돌리는 기능이 아니다.

## 후속 검증 조건

제품 구현 전 입력 정책과 남은 단축키 확인을 합의한다. 아래 방향의 전체 숨김·복원 의미는 사용자 확인 완료다. 이후 순수 방향 판정(떨림·대각선·부분 키 해제·Esc·휠 우선·한 번 실행), 안정된 생성 순서 및 화면 부족 계산을 시험한다. 별도 개발 인스턴스에서 실제 키/포인터로 펼침·접힘 혼합, 두 번째 아래, 수동 크기/warp 포함, 숨김 제외, 초안·포커스 보존, 연속 명령·전환 중 입력, PTY 최종 cols/rows, 다중 모니터 경계·화면 해제를 검증한다.
