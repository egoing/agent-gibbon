# 마지막 터미널·앱을 알려주고 다시 실행하기

조회일: **2026-11-13 (Asia/Seoul)** · 조사 이슈 [#153](https://github.com/egoing/agent-gibbon/issues/153) · 계획 Draft PR [#155](https://github.com/egoing/agent-gibbon/pull/155).

## 결론과 권장 선택

**가능하다. 우선 ‘이 창에서 마지막으로 명시 실행한 앱 + 그 실행 폴더’를 기억하고, 다시 연 Welcome에서 보여 준 뒤 기존 실행 버튼 한 번으로 새 실행하는 방안을 권장한다.** 예를 들어 ‘마지막 실행: Codex · project’와 실제 실행 미리보기를 보여 주고 `Codex 새로 실행`을 누르는 형태다. 앱/폴더를 바꾸면 미리보기와 실행 대상도 함께 바뀌어야 한다. 이것은 제안이며 현재 UI 확정 규칙이 아니다.

이 방식은 종료 전 대화를 이어 주지 않는다. 대화가 필요하면 2단계로 CLI 자체의 세션 선택기를 열고 사용자가 고르게 하는 기능을 추가하는 편이 안전하다. ‘바로 그 대화’를 한 번에 재개하려면 창별로 검증된 세션 ID까지 연결해야 한다. 임의 명령·히스토리 전체를 수집하는 방식은 권장하지 않는다.

현재는 앱 ID가 남아 있지 않으므로 과거 창의 마지막 앱을 소급해서 알아낼 수 없다. 최초 도입 이전 기록은 ‘마지막 앱 정보 없음’으로 표시해야 한다. #150의 명령 미리보기로 이를 추측해서는 안 된다.

## 무엇을 다시 여는가

| 대상 | 의미 | 현재 가능한 범위 | 필요한 선택 |
|---|---|---|---|
| 터미널 창 | 메모 ID·배치·Welcome | 닫힌 항목 재열기 지원. 앱 재시작 시 배치 복원은 #150 진행 중 | 현재 창과 새 창을 구분 |
| 셸 | zsh/PowerShell 등 새 프로세스 | 기본 셸을 새로 실행 | 이전 셸 종류까지 고정할지, 현재 기본 셸을 쓸지 |
| 작업 폴더 | 실행 cwd / 마지막 관측 cwd | 창별 마지막 폴더·최근 폴더 저장 | 앱을 시작했던 폴더와 나중에 이동한 폴더 중 어느 것을 사용할지 |
| 앱 | Codex/Claude Code/git log/htop | 추천에서 명시 선택해 새 실행. 선택 앱 ID는 미저장 | ‘최근 선택 앱’으로 한정할지 셸 직접 실행도 추적할지 |

앱이 종료되고 셸이 남아 있다면 ‘실행 중인 앱’은 셸이고 ‘마지막으로 실행한 앱’은 Codex일 수 있다. 추천에서 Codex를 시작한 뒤 셸에서 Claude를 직접 실행했다면 기존 코드로 마지막 앱을 Claude라고 확정할 수 없다. 권장안은 ‘마지막 추천 실행’이라고 정확하게 이름 붙인다. 사용자가 말한 ‘마지막으로 작업’이 최근 포커스인지, 마지막 실행 시각인지도 다르므로 전역 단일 최근 기록보다 창별 기록을 우선한다.

## 현재 코드와 인접 작업의 근거

기준 root `/Users/egoinglee/.codex/worktrees/bb80/agent-gibbon`, origin/main `9904f10770d552b8f90ceb8073415d9875c09062`, 조사 브랜치 `codex/terminal-relaunch-research`, 첫 계획 HEAD `b3c06a2cbd6f84c0392621175af6714bbc874981`.

- `src-tauri/src/terminal.rs`: `Terminal`은 ID·배치·종류·마지막 경로·최근 경로·시각·제목을 직렬화한다. 명령/대화/앱 ID/세션 ID는 저장하지 않는다. 테스트 `welcome_metadata_preserves_only_last_path_title_and_geometry`도 history/commands 부재를 확인한다. 메모리의 `Session.program`은 셸로 설정되어 있어 추천 앱 식별 근거가 아니다.
- `src-tauri/src/terminal/welcome.rs`: `command`는 앱 ID allowlist를 고정 명령으로 매핑하고 PATH/설치 경로에서 실행 파일 존재를 확인한다. `start`는 cwd 유효성을 검사하고 `start_shell`은 새 PTY·대화형 셸을 만든다. Unix에서는 인용된 고정 명령을 셸 입력으로 전달하며 Windows에서는 PowerShell 명령 인수에 포함한다. 앱 종료 뒤 셸 유지라는 현재 계약을 바꾸지 않고 이 지점에 명시 실행 메타데이터를 추가하는 것은 가능하다.
- cwd는 macOS 프로세스 조회·Linux `/proc` 및 Windows 디렉터리 보고 경로를 사용한다. 현재 관측은 모든 자식 프로세스의 실제 작업 폴더나 마지막 활동을 증명하지 않는다.
- `terminal.rs`의 시작 슬롯/토큰은 시작 중인 같은 ID의 경합을 다룬다. 재실행 경로도 이 생명주기를 통과해야 하며 새 별도 우회 spawn 경로를 만들면 안 된다.
- [디자인 시스템](../design-system.md), [시안 SVG](../design/terminal-welcome.svg), [PNG](../design/terminal-welcome.png): 폴더/앱 선택만으로 실행하지 않고 별도 실행 버튼과 읽기 전용 미리보기를 제공한다. 명령·출력·대화·히스토리 미저장 및 resume 미지원이 현재 확정 범위다. 이번 문서는 새 정책을 확정하지 않으며 디자인 시스템/시안은 변경하지 않았다.

## CLI 새 실행과 대화 재개

아래는 문서·help에서 확인한 형식이며 **실제로 실행하거나 대화를 재개하지 않았다**. 초기 프롬프트를 붙이지 않아도 CLI 시작 시 설정·플러그인·MCP·훅을 읽을 수 있으므로 앱 실행 자체가 무해한 조회라는 뜻은 아니다. 권한 우회 옵션은 생성하지 않는다.

| 앱 | 새 실행 | 재개 선택 | 제한과 판단 |
|---|---|---|---|
| Codex CLI | `codex` | `codex resume` 선택기, `codex resume <SESSION_ID>`, `codex resume --last` | 공식 문서상 `--last`는 현재 cwd 기준, `--all`은 다른 폴더까지 확장. 같은 cwd의 다른 창 세션과 혼동할 수 있으므로 자동 채택 금지 |
| Claude Code | `claude` | `claude --resume` 선택기, `claude --resume <ID 또는 이름>`, `claude --continue` | `--continue`는 현재 폴더의 최근 대화. 창과 일대일 대응하지 않음. 이름보다 고유 ID가 매핑에 적합 |
| 셸·git log·htop | 현재 고정 추천 실행 | 대화 세션 재개와 무관 | shell history·스크롤백·이전 작업의 메모리를 복원하지 않음 |

Codex 문서는 저장 cwd와 현재 cwd가 다르면 선택을 묻고 명시 `-C/--cd`가 우선한다고 설명한다. 폴더 변경 시 이를 앱이 몰래 덮어쓰지 않는다. Claude `--fork-session`은 재개 시 새 세션 ID를 만들고 Codex `fork`는 대화 분기를 만든다. 이는 원래 대화 재개와 다른 동작이므로 ‘다시 실행’의 숨은 기본값으로 쓰지 않는다.

CLI의 기록 비활성화·보관 만료·삭제, 계정/프로필/CLI home 변경으로 세션이 없을 수 있다. 실패 시 새 대화로 조용히 대체하거나 다른 최근 세션을 열지 않고, ‘선택기로 찾기 / 새 실행 / 취소’를 제공한다. Desktop 채팅 ID와 CLI 세션 ID가 동일하게 호환된다고 전제하지 않는다. 현재 제품은 이를 연결하는 공식 통합을 갖추지 않았다.

## 저장·실행의 안전 설계 제안

추천안의 레코드는 `schema_version`, 창 ID, `app_id` enum, `launch_cwd`, 선택적으로 `last_observed_cwd`, 마지막 명시 실행 시각, `mode=new` 정도로 제한한다. 셸은 `current_default` 정책 또는 검증된 shell ID로 구별한다. 프로세스 생성 실패를 ‘실행 성공’으로 남기지 않되, PTY 생성 성공만으로 앱 로딩 완료를 단정하지 않는다. 문자열 명령/자유 argv/환경 전체/출력/대화는 저장하지 않는다. 세션 재개를 선택하면 별도 `provider+session_id`를 사용자 명시 연결로 추가하고 ID도 민감한 로컬 메타데이터로 취급한다.

| 경계 | 주의점과 제안 |
|---|---|
| argv·cwd | 저장된 문자열을 `sh -c`/`eval`에 넣지 않는다. 앱 ID를 백엔드 allowlist의 고정 인수 배열로 변환하고 cwd는 별도 설정한다. NUL/제어문자·잘못된 스키마·알 수 없는 enum을 거절한다. 공백·따옴표·달러·백틱을 가진 경로가 명령이 되지 않는지 시험한다 |
| 현재 셸 계약 | 현재는 앱 종료 뒤 셸 복귀를 위해 셸 문자열을 전달한다. 직접 argv spawn으로 단순 치환하면 이 계약이 달라진다. 고정 wrapper/셸별 안전 인용·adapter 또는 명시 PTY 전환 설계를 검토해야 하며 Rust Command 사용만으로 현재 셸 경유 경로의 주입 위험이 자동 해소되지는 않는다 |
| Windows | `.cmd/.bat`는 셸 처리 예외가 있으므로 Unix 인용을 재사용하지 않는다. PowerShell `-LiteralPath`, 고정 invocation, 설치 wrapper와 악의적 파일명 경계를 별도 검증한다 |
| 환경·비밀 | 이전 env를 snapshot/복원하지 않는다. API 키·토큰·명령 인수·history·프로세스 argv 스캔을 수집하지 않는다. 새 실행은 현재 인증/환경 정책을 따르며 과거와 달라질 수 있음을 안내한다. 정상 셸 초기화 파일도 명령을 실행할 수 있다 |
| 설치 경로 | 저장한 과거 executable 절대 경로를 무조건 신뢰하지 않는다. 현재 허용된 탐색기로 재해석하고 이전과 경로/버전이 바뀌면 미리보기 갱신과 확인 기회를 준다. PATH의 다른 동일명 파일·wrapper는 존재만으로 신뢰되지 않는다. 앱 부재 시 자동 설치/다른 앱 대체 금지 |
| 폴더 변경 | 삭제·권한 변경·외장 디스크 미연결·symlink 변경·다른 repo/worktree 교체를 검사한다. 없으면 홈으로 몰래 실행하지 않고 폴더 선택을 요구한다. 실행 cwd와 마지막 관측 cwd를 섞지 않는다. 검증 후 spawn까지의 변경 경쟁은 오류 처리로 막는다 |
| 복수 터미널 | 키는 `instance+terminal_id`이고 세션 연결은 provider와 ID까지 포함한다. 전역 ‘최근’으로 각 창의 기록을 덮어쓰지 않는다. 같은 cwd의 A/B 앱과 대화를 서로 바꾸지 않는다. 전역 최근 표시는 명시 실행 시각 기준으로 정의하며 최근 포커스라고 주장하지 않는다 |
| 중복 클릭 | UI 실행 중 비활성화 + 백엔드 원자적 Starting 슬롯/토큰 + 요청 식별자로 같은 창의 PTY 하나만 만든다. 실패/취소/창 삭제/재시작 시 토큰 정리. 이미 살아 있는 숨긴 PTY는 새 실행 대신 기존 세션을 표시한다 |
| 종료·복원 | 저장 상태는 실행 지시가 아니다. 시작/업데이트/Welcome 복원으로 spawn하지 않는다. 종료된 PID를 재사용해 attach/kill하지 않는다. 이전 작업이 실제로 끝났는지 모를 때 OS 이름만 보고 종료하지 않는다. 사용자 명시 실행 전 이전 프로세스 종료와 새 실행/재개의 차이를 표시한다 |
| 보관·삭제 | 창마다 최신 1개만, opt-out·기록 지우기·창 삭제 시 연관 기록 제거를 제안한다. 폴더/앱 정보도 개인정보일 수 있다. 별도 무기한 이력은 만들지 않는다. 원자적 로컬 저장·사용자 권한·크기 제한·스키마 검증, 개발 인스턴스 분리, 진단/텔레메트리/PR 첨부 배제를 적용한다 |
| 삭제의 범위 | 앱 메타데이터 삭제는 CLI 자체의 대화/셸 히스토리 삭제가 아니다. 복원 snapshot·업데이트 snapshot에도 남지 않게 삭제 규칙을 통일한다. 디스크/OS 백업의 완전 삭제를 보장한다고 표현하지 않는다 |

‘마지막 임의 명령’을 정확히 알아내려면 셸 integration/hook 등 실행 경계가 필요하다. PTY 입력은 편집·붙여넣기·비밀번호·TUI 대화를 섞으며 프로세스 이름은 별칭·wrapper·ssh·tmux·중첩 셸을 식별하지 못한다. 명령의 비밀값을 정규식으로 완전히 제거할 수 없고 겉보기에 단순한 명령도 별칭/설정 때문에 부작용이 있을 수 있다. 원문 수집 후 마스킹보다 수집하지 않는 설계가 낫다.

## 대안 비교

| 권장 순서 | 방안·범위 | 장점 | 한계·위험 | 예상 Risk |
|---|---|---|---|---|
| 1 | 창별 마지막 명시 추천 앱 ID+실행 cwd 저장, Welcome에 미리 선택, 실행 한 번으로 새 시작 | 가장 작은 변경, 임의 명령 불필요, 기존 Welcome 재사용 | 셸 직접 실행과 과거 대화는 알 수 없음. UI·저장 정책 확장 승인 필요 | Medium: 저장 상태·PTY 수명 경계 |
| 2 | 1에 ‘대화 선택해 재개’를 별도 제공, CLI 공식 선택기 사용 | 앱이 대화 원문을 수집하지 않아도 재개 가능 | 첫 클릭은 선택기 실행이고 실제 대화 선택은 추가 조작. 정확한 한 번 재개는 ID 연결과 별도 공식 adapter가 필요 | Medium: 잘못된 대화/폴더 선택·권한 설정 |
| 3 | 임의 명령/프로세스 추적과 자동 세션 ID 수집 | 직접 입력한 앱까지 더 넓게 포착할 가능성 | 정확성 보장 어려움, shell별 integration과 개인정보 수집 확대, 명령 재실행의 금전/삭제 부작용 | High 가능: 임의 명령 재실행. 우선 채택 비권장 |

첫 번째는 요구를 ‘마지막으로 앱에서 실행한 앱을 알려 주고 다시 새로 시작’으로 합의할 경우 적합하다. 두 번째는 사용자가 대화 연속성을 원할 때만 후속으로 택한다. 세 번째는 단지 앱 이름을 알려주려는 요구에 비해 비용과 위험이 크다. 종료된 프로세스의 메모리를 복구하거나 임의 외부 앱을 찾아 되살리는 방안은 이번 목표와 분리한다.

## 사용자에게 필요한 선택

1. 권장: ‘마지막 작업 앱’은 **이 창에서 추천으로 마지막 명시 실행한 앱**으로 정의한다. 셸에서 직접 바꾼 앱은 추적하지 않는다.
2. 권장: 기본은 **새 실행**, 대화 재개는 별도 선택기 기능으로 보류한다. 정확한 ID 재개는 별도 설계·승인한다.
3. 권장: 재실행 기본 폴더는 **그 앱을 실행했던 폴더**, 마지막 관측 폴더는 별도로 보여 주고 사용자가 선택한다. 기존 최근 폴더 기능은 유지한다.
4. 권장: 기록은 창별 최신 1개만 로컬 저장하고 삭제/기록 끄기를 제공한다. 보관 기간 상한을 추가할지는 사용자 선택이다.
5. 원클릭 의미: **다시 연 Welcome에서 이미 선택·미리보기된 앱을 실행 버튼 한 번으로 시작**한다. 창 열기 자체를 실행 트리거로 삼지 않는다. 이는 기존 선택→별도 실행 구조를 유지하는 제안이다.

## 구현을 선택할 때의 완료 기준

- 앱 A와 앱 B를 서로 다른 폴더/창에 실행한 뒤 정상 종료·비정상 종료·앱 재시작·업데이트 복원에서도 올바른 창에 앱/실행 cwd가 표시된다. 예전 데이터는 정보 없음으로 읽으며 자동 spawn이 0회다.
- 앱을 종료하고 셸이 남은 경우, 숨겨 살아 있는 경우, 셸이 끝난 경우를 구분한다. 사용자 클릭 한 번에 해당 창의 새 PTY는 최대 하나이며 이미 실행 중이면 중복 생성하지 않는다.
- 경로의 공백·따옴표·셸 메타문자, 사라진/바뀐 폴더, PATH 변경, 앱 삭제·버전 불일치, spawn 실패에서 안전하게 거절/안내하고 포커스·위치·숨김 상태를 보존한다.
- 원문 명령·환경변수·출력·대화를 저장/전송하지 않으며 기록 지우기·창 삭제 후 모든 앱 소유 snapshot에서 재등장하지 않는다. 실제 CLI 자체의 기록은 범위 밖임을 명시한다.
- 재개 기능을 채택하면 같은 cwd의 서로 다른 두 대화를 매핑 혼동 없이 확인한다. ID 부재/삭제/다른 profile은 명시 실패 처리하며 `--last`/`--continue`로 몰래 대체하지 않는다. 초기 프롬프트·권한 우회·비대화형 실행을 생성하지 않는다.
- 구현 전에 디자인 시스템의 저장/재개 범위와 문구를 승인받고, 외형 변경 시 SVG/PNG도 갱신한다. 해당 플랫폼의 로컬 검사와 출처가 확인된 개발 인스턴스 실검증을 수행한다. 전체 플랫폼 CI는 별도 명시 요청 또는 배포 준비에서만 실행한다.

## 이번 조사 검증과 한계

문서·코드 정적 비교, 관련 이슈 검색(최근 종료 포함), 공식 페이지 열람, 지정 CLI의 help/버전 조회를 수행했다. 문서 상대 링크와 `git diff --check`를 확인했다. 제품 코드·설정·디자인 시스템 변경은 없고 앱 실행·빌드·사용자 대화/이력 열람·실제 재개·GUI·Windows/Intel 실검증·전체 플랫폼 CI는 수행하지 않았다. 공식 옵션 존재 확인은 실제 복원 성공의 증거가 아니다.

**Conf 1**: 코드/문서 검토와 help 조회이며 제품 실행 검증 없음. **이번 변경 Risk Low**: 로컬 조사 문서만 추가. 구현 방안의 위험은 위 표의 별도 평가이며 이번 문서 위험과 혼동하지 않는다. 조사 결과 파일은 최종 커밋·push·병합 승인 대기 상태다.

## 복원 화면 제안 시안 — 2026-11-13

사용자 요청으로 [SVG 와이어프레임](terminal-restore-wireframe.svg)과 [PNG](terminal-restore-wireframe.png)를 작성하고 렌더링 결과를 확인했다. 정상 기록과 폴더 부재 상태를 비교한다. 마지막 명시 실행 앱·폴더·실제 실행 미리보기를 제공하고 선택 후 별도 실행을 유지한다. 폴더 부재 시 실행을 막고 폴더 선택을 제공한다. 기록이 없으면 기존 Welcome을 사용한다. 대화 재개는 이번 시안에 포함하지 않는다. 설명용 제안이며 디자인 시스템 확정 규칙이나 제품 구현을 변경하지 않았다. native GUI·좁은 폭·접근성 검증은 미실행이다.

## 후속 사용자 결정과 최종 구현

앞선 비교·권장안과 복잡한 와이어프레임은 최초 조사 당시 제안이다. 이후 사용자 결정으로 한 줄 실행 계획·복원·취소의 간단한 화면을 구현했다. 셸에서 직접 실행한 명령도 이름 중심으로 기록하며 macOS의 검증된 무인자 모니터는 자동으로 다시 실행한다.
