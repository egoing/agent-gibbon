# 자동 업데이트 실증 체크리스트

대상은 iMac Intel과 Windows x64의 정식 v0.2.10 → v0.2.11 업데이트다. 각 시나리오는 이전 버전에서 시작한다. 관찰 중 확인된 사실만 완료로 표시한다.

## 최신 검증 빌드 판정 (11월 8일)

| 시험 | iMac Intel | Windows x64 |
|---|---|---|
| 자동 설치·재시작 | 표준 300초 무입력으로 확인 | quiet 모드 45초 무입력으로 확인 |
| 메모 전후 복원 | 표준 회차 A/B 본문·위치·크기·표시 일치 | 수정 전 375×60→375×97 재현. 수정 후 두 메모 375×60·위치·본문 유지 |
| 미저장 편집 보호 | 실제 편집 창의 거부와 저장 후 새 버전에서 본문 유지 확인 | 창 #6 editing=true로 거부, 저장 전 기준 본문 유지, 저장 후 revision 증가 |
| 터미널 보호 | 342초 무입력 후에도 셸 유지, 종료 후 자동 설치 | 65초 무입력에도 같은 실행 PTY 유지. 정상 종료 후 v0.2.12 자동 재시작 |
| 수동 설치 | 표준 설정 버튼 클릭 후 재시작 확인 | 편집 메모 저장 후 설정의 재시작하여 설치 클릭, v0.2.12 PID 24496 확인 |
| 기존 배포판과의 호환 | 이전 실증 이력은 아래에 보관 | /P 구버전과 언어 선택 없는 후보 조합 통과 |

### 현재 관찰
- iMac은 무입력 5분을 넘긴 시점에 편집·저장 중인 창이 있다는 이유로 설치가 보류됐다. 이후 원격 입력으로 무입력 시간이 초기화됐고, 다시 5분 이상 무입력 상태를 관찰했지만 설치가 보류된 채였다. 구체적인 차단 창·조건은 미확정이다. 이후 다시 무입력 상태에서 자동 설치가 성공했다.
- Windows는 v0.2.11 프로세스가 실행됐다. 메모 내용·표시·위치·고정은 유지됐으며 높이가 60에서 97로 바뀌어 원인과 안정화 여부를 확인 중이다.

## 제한과 남은 확인
- 앱 설치를 시작하기 전부터 OS가 이미 무입력 상태일 수 있으므로 앱 시작 후 5분과 마지막 입력 후 5분을 각각 기록한다.
- 다른 플랫폼의 결과를 대신 사용하지 않는다. 실제로 실행하지 않은 시나리오는 완료 처리하지 않는다.
- 외부 환경이나 사용자 조작 때문에 조건이 바뀌면 시각과 영향을 기록한다.

## 증거와 해석 범위

- iMac 설치 대상: `/Applications/Agent Gibbon.app`, Intel 정식 v0.2.10. 앱이 받은 v0.2.11 패키지 SHA-256은 `3454f100688256bc4e9d7083df8eee5bad1bf75957408cf3098efbc6f0a0dc9b`이며 공식 자산과 일치했다. 구버전 공식 DMG SHA-256은 `278a20df2260331efe0982bf99cadff7d08d5acaa9d4bb625093b0bdb9f206c2`다.
- iMac 읽기 메모 안정화 후 기준: 두 메모 모두 600×98, 표시·항상 위 고정 상태였고 위치는 각각 (3240, 1966), (3240, 1868)이었다. 업데이트가 완료되지 않아 설치 후 비교는 아직 불가능하다.
- 코드상 설치 보호는 각 창에 안전 여부를 확인하고, 편집·저장 이외에 처리 중인 로컬 호출이 있어도 안전하지 않다고 응답할 수 있다. 이번 iMac에서 실제로 어느 창과 조건이 거부했는지는 확인되지 않았으며, 이 코드 검토만으로 관찰된 보류의 원인으로 단정하지 않는다.
- 11월 8일 00:11:53 Windows: 무입력 대기 후에도 v0.2.10 PID 22768이 유지됐고, v0.2.11 준비 상태에서 ‘편집·저장 중인 창이 있어 설치를 보류했습니다’로 메시지가 바뀌었다. 00:12 화면에 편집 저장·취소 버튼과 업데이트 안내가 유지됐다. 메모 열기는 시작 1초 이내였지만 편집 전환의 15초 이내 여부와 미저장 텍스트 보존은 확인하지 못했다.
- 11월 8일 00:12:29 iMac에서 OS 무입력 306.7초, v0.2.10 준비 상태를 확인했다. 00:12:50경 진단에서 v0.2.11 revision `e0b478d76ca0` 실행을 확인했다. 그 사이 자동 설치와 재시작이 일어났으며 정확한 전환 시각은 미측정이다. 두 검증 메모의 내용·위치·600×98 크기·표시·고정 상태가 안정화 후 기준과 모두 일치했다. 첫 무입력 시도는 보류됐으므로 시작 후 5분 15초에 성공했다고 해석하지 않는다.
- 11월 8일 00:13:09 Windows에서 편집 취소 후 수동 ‘재시작하여 설치’를 눌러 5분 무입력 대기 없이 v0.2.11 revision `e0b478d76ca0`, PID 13052 실행을 확인했다. 메모 복원 비교는 진행 중이다.
- iMac 수동 시험을 위해 공식 v0.2.10 DMG를 읽기 전용 마운트하고 기존 v0.2.11 앱을 백업한 뒤 00:14:39 구버전을 실행했다. 시작 직후 캐시된 업데이트 설치는 창 크기 조정 보류, 이후 편집·저장 보류로 나타났다. 설정의 수동 설치 화면에 도달하기 전에 앱이 다시 v0.2.11로 자동 전환되어 이 시도는 수동 설치 검증으로 인정하지 않는다. 일반 종료 후 검증용 메모 두 개는 숨김으로 시작해 직접 다시 열었다.
- 11월 8일 00:16:49 iMac을 공식 v0.2.10으로 다시 실행했다. 설정 화면에 현재 0.2.10, 새 버전 0.2.11 및 최근 입력에 따른 자동 설치 보류가 표시된 상태에서 00:17~00:18 수동 ‘재시작하여 설치’를 여러 차례 눌렀으나 매번 편집·저장 중인 창 때문에 보류된다고 표시됐다. 이 시도에서 수동 설치는 성공하지 않았으며 차단 창은 미확인이다.

## 최종 상태와 미완료

- 두 컴퓨터 모두 v0.2.11 실행 확인. Windows는 업데이트 기능으로, iMac은 최종적으로 시험 전 백업 복구로 최신 버전을 유지한다.
- Windows: 읽기 메모 자동 설치, 편집 화면 보호, 실행 중 터미널 보호, 수동 설치를 확인했다. 편집·터미널의 시작 15초 이내 여부, 미저장 텍스트 보존, 읽기 메모 높이 변화의 원인은 미검증이다.
- iMac: 읽기 메모 자동 설치와 메모 복원을 확인했으나 첫 시도는 반복 보류됐고 나중에 성공했다. 수동 설치는 여러 차례 보류돼 성공하지 못했다. 화면 기록 권한이 시스템 설정에서 켜져 있음에도 앱이 요청해 터미널 보호는 시험하지 못했다.

- Windows 진단 빌드 PTY 보호 재시험 통과. 1차에는 검증 manifest 서명 불일치로 다운로드 검증 실패. canonical 서명으로 교체 후 HTTP 응답 일치 확인. 65초 무입력 뒤 .11 유지, .12 준비 완료 및 ‘터미널 작업이 실행 중이거나 시작되고 있습니다’ 보류 사유 확인. terminal-1029002 셸 PID 35856, running=true, visible=true 유지.
- Windows PTY 정상 종료 후 running=false/pid=null. 35초 무입력 뒤 검증 앱 v0.2.12 PID 24136으로 재실행, epoch 1 prepared 및 모든 창 ACK 확인.
- Windows 편집·수동 설치 회차 통과. v0.2.11이 .12 다운로드를 마친 상태에서 epoch 26 메모 #6 편집 중·거부, 원본 본문 불변. 저장 후 revision 3과 실제 변경된 본문 확인(원격 입력기의 글리프가 예상과 달랐음). 설정의 수동 재시작 버튼 클릭 후 epoch 27 안전 응답과 v0.2.12 PID 24496 확인.
- 진단 조회가 설치 준비 예약 중 간헐 보류되는 문제도 확인했다. 읽기 전용 diagnostics를 예약 이전으로 이동했으며 이 후속 변경은 로컬 검사를 수행했다. 실기기에서 사용한 이전 빌드는 재시도 조회로 근거를 확보했다.
- 정리 완료. Windows 검증 앱·전용 피드·시험용 절전 방지 프로세스 종료. terminal-1029002 fixture만 제거, 테스트 메모와 증거 보존. 임시 개인키 폐기. 일반 앱은 종료 후 프로세스 목록에서 관찰되지 않았고 정식 설치 파일/사용자 저장소는 이번 격리 회차의 교체 대상이 아니었다.
- 판정 범위: 이번 Windows 검증은 30초 무입력 프로필, iMac은 300초 기본값도 시험했다. 모든 보호 회차의 앱 실행 후 15초 이내 진입은 입증하지 못했다. 과거 iMac 정식판의 오탐 원인은 당시 창별 진단 부재로 미확정이다.
