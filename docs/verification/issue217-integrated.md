## 37번 macOS 실기기 검증

작업 루트는 `/Users/egoinglee/.codex/worktrees/90e5/agent-gibbon`이다. 정규 빌드의 개발 CLI로 `overview37-d4b60d-a`를 열고 inspect 응답의 본문과 인스턴스 ID, PID 32556의 실행 경로와 창 제목을 대조했다. 다른 인스턴스가 전역 단축키를 사용하고 있어 실기기 시험 빌드에서 왼쪽·오른쪽·위쪽 입력을 제품의 방향 처리 함수에 전달했다. 자동 정렬·닫기는 실제 버튼을 macOS 접근성 API로 눌렀고 개별 창 이동·크기 변경도 같은 API로 수행했다.

두 차례 실행한 PID는 33378과 45155이며 검증 메모 접두사는 각각 `overview37-3171cf`와 `overview37-918e8f`였다. 텍스트 두 개, 이미지, 터미널, 웹 창에서 좌우 대칭 배치와 위쪽 진입 시 프레임 보존을 확인했다. 자동 정렬 후 수동 이동한 위치가 위쪽 입력 반복에도 유지됐고 닫기 후 다섯 창의 좌표와 크기가 진입값과 일치했다. 재진입 시 새 좌표를 사용했고 이전 세션의 버튼 요청은 무시됐다.

편집한 본문, 핀 해제·접힘, 개별 숨김, 외부 앱 포커스가 유지됐다. 첫 실행에서 셸 PID 33760이 유지됐고 PTY가 37×25에서 37×26을 거쳐 37×25로 돌아왔다. 웹 자식 뷰도 588×780에서 588×790을 거쳐 원래 크기로 돌아왔다.

## 메모 모아보기 후속 변경

창 포커스 없이 닫기·자동 정렬 사이를 이동하고 버튼 밖으로 나가는 이벤트를 시험했다. Chromium에서 네이티브 이벤트를 대역으로 전달해 버튼 배경색과 비포커스 상태, 키보드 실행, 밝고 어두운 배경막의 알파 0.84를 확인했다. Rust 308개 통과·기존 제외 1개, UI 224개 통과, Clippy와 정규 개발 빌드 통과. 개별 창은 모아보기 동안 네이티브 알파 1을 적용하고 닫기 시 기존 창 전환 엔진으로 위치와 크기를 복원한다. 이 변경 이후의 네이티브 검증에서는 기존 사용자 창이 함께 발견되어 방향 입력 전에 중단했다. 실기기에서의 첫 호버, 창 불투명도와 복원 중간 프레임은 아직 확인하지 않았다.
