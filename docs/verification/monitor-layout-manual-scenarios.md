# 모니터 환경 변경 수동 확인 — #190

이 문서는 사용자와 함께 진행할 검증 순서다. 아래 체크는 실제 결과 확인 전까지 완료하지 않는다. 에이전트는 해당 워크트리의 고유 메모만 준비하고 모니터 설정·연결은 사용자가 직접 변경한다.

## 먼저 할 핵심 시험

| 단계 | 사용자 행동 | 기대 결과 | 실패 징후·복구 |
|---|---|---|---|
| 1 | 준비된 A/B/C 위치를 확인하고 지정한 외부 모니터를 분리 | A는 그대로, B/C는 남은 화면으로 피난. 툴바와 크기 조절 영역에 접근 가능 | 창이 사라지거나 툴바가 가려짐, A가 불필요하게 움직임. 화면을 다시 연결하고 실패한 메모 이름을 알려준다 |
| 2 | 분리 중 **C만** 툴바로 직접 옮기고 크기도 조금 바꿈 | C의 새 위치·크기가 사용자 선택으로 기록됨. B는 건드리지 않음 | 이동 직후 되돌아오거나 자동으로 다시 정렬됨. 더 조작하지 않고 상태를 알려준다 |
| 3 | 같은 외부 모니터를 다시 연결 | B는 원래 위치·크기로 복귀, C는 직접 정한 새 위치·크기 유지. 숨긴 H는 계속 숨김 | C가 원위치로 끌려감, B가 돌아오지 않음, H가 표시되거나 다른 앱의 포커스를 뺏음 |

A/B/C 이름과 초기 위치·크기는 준비 결과 JSON에 기록한다. C를 사용자가 옮긴 뒤에는 **그 최신 상태가 검증 기준**이며, 에이전트가 초기 배치로 덮어쓰지 않는다. 1~3을 먼저 확인한 뒤 다음 시험을 이어간다.

## 핵심 시험 후 이어갈 순서

| 시험 | 사용자 행동 | 확인할 결과·원복 |
|---|---|---|
| 작은 작업 영역 | 지정한 테스트 창을 크게 한 뒤 해당 화면 해상도/배율을 변경 | 작업 영역보다 크면 임시 축소, 툴바·resize 접근 유지. 기존 설정으로 돌아오면 자동 보정만 된 창은 원래 크기로 복귀. 직접 resize한 창은 최신 크기 유지 |
| 숨김·접힘·핀 | 테스트 H 숨김, B 접기 또는 핀 변경 후 분리·재연결 | 숨긴 H를 열지 않음. 접힘·핀 유지, 펼치면 필요한 만큼 보정. 실제 사용자 메모로 하지 않음 |
| 확대·원복 | 테스트 창 툴바 빈 곳 더블클릭으로 확대 후 환경 변경, 다시 더블클릭 | 새 작업 영역에 맞추되 확대 전 위치·크기를 잃지 않음. 원래 화면 부재 시 복원 위치도 안전 영역으로 보정 |
| 방향 정렬·5초 취소 | 지정 테스트 메모에서 방향 정렬 후 즉시 취소 | 정렬 전 위치와 모니터 복귀 관계를 함께 복원. 이후 재연결 때 명시 조작 우선 기준 유지. 정렬은 기존 메모도 움직일 수 있으므로 **별도 격리·사용자 동의 후** 실행 |
| 임시 배치 중 재시작 | 외부 화면이 없는 동안 테스트 인스턴스만 재시작한 뒤 재연결 | 임시 배치와 원래 배치를 각각 보존. 숨김/접힘·확대 이전 크기 유지. 팀장 조율 아래 정확한 binary/PID만 재시작 |
| 창 유형 | 별도 전용 이미지·터미널·웹 세트를 준비해 위 시험 반복 | 이미지 원본/비율, PTY 최종 셀·실행 세션, 웹 child 영역과 로딩 상태를 보존. 실제 미검증 항목은 미완료로 남김 |

## 관찰과 복구 원칙

- 자동 보정은 포커스를 요청하거나 숨긴 창을 열지 않는다. 사용자의 디스플레이 설정 조작 자체에 따른 OS 포커스 변화는 구분한다.
- 재연결 시 화면 식별 정보가 달라졌다면 잘못된 곳으로 복귀하는 대신 안전 배치를 유지할 수 있다. CLI의 모니터 진단과 전후 화면 정보를 비교해 원인을 판정한다.
- 화면이 너무 작거나 창이 너무 많아 전부 노출할 수 없다면 임의로 닫거나 숨기지 않는다. 현재 메모 관리/트레이의 개별 열기 또는 CLI로 지정 테스트 창에 접근하고 부족한 화면 용량을 기록한다.
- 복구는 우선 같은 케이블·화면 설정으로 되돌린 뒤 진행한다. 불확실한 상태에서 전체 정렬이나 기존 사용자 창 이동을 시도하지 않는다.
- 준비 세트·시작 전후 상태와 앱 출처는 `monitor-layout/manual-prepared.json`에 기록한다. 물리 전환 결과는 사용자의 실제 관찰·inspect 전후 기록을 확보한 뒤 추가한다.
