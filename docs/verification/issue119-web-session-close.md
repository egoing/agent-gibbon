# 웹 창을 닫을 때의 세션 종료 (#119)

현 main(22dc7de)의 웹 Welcome과 원격 페이지에는 이미 핀이 있다. 툴바 X와 OS 닫기는 호스트를 숨겨 세션과 URL 복원 기록, 업데이트 보류 사유를 남긴다.

- 현재 단일 호스트·원격 자식 구조에서 두 사용자 닫기 경로를 연결한다. CLI close와 전체 숨김은 세션을 보존한다.
- 닫은 호스트에 귀속된 탐색 상태와 복원 기록을 정리하고 다른 ID와 같은 ID의 다음 세대를 보존한다.
- 상태 전이와 재시작 기록을 Rust 테스트로 확인하고 웹 툴바 이벤트와 핀을 따로 검증한다. 네이티브 실험 범위는 구분해 기록한다.
- 기존 PR #129는 다른 기준 브랜치와 과거 창 구조, CLI close의 다른 의미를 전제로 한다. 그 브랜치의 제품 변경은 가져오지 않는다. #184 목록 UI는 별도 작업이다.

## 구현과 검증 (2026-11-16)

툴바 X와 OS 닫기가 호스트 소유 세션의 종료 경로를 공유한다. 종료 요청 시 로컬 시작 기록에서 대상 웹 창을 원자적으로 제거하고 Tauri에 호스트 파괴를 요청한다. 디스패치 실패 시 기록을 복구한다. 호스트의 Destroyed 이벤트까지 관리 레코드를 유지하므로 네이티브 창이 남은 동안 업데이트 안전 검사가 작동한다. 닫기 요청 중에는 같은 ID의 재열기를 거절하며, 새 세션은 자신만의 탐색 상태를 가진다. HTTP(S) 검증, 원격 자식의 invoke 거절, 팝업·다운로드 거부를 유지했다. 최근 주소 목록은 복원 기록과 독립적이다.

| 확인 항목 | 결과 |
|---|---|
| Rust 상태 전이 | 첫 종료 실패 후 재시도, 중복 요청의 단일 처리, Destroyed 후 해당 레코드 해제, 두 웹 창 중 마지막 창의 업데이트 판정, 이전 세대의 지연 탐색·Destroyed와 같은 ID 재생성 통과 |
| 로컬 시작 기록 | 실제 임시 파일을 다시 읽어 닫은 URL과 모니터 기하 제거, 다른 웹·텍스트·이미지·터미널 항목 보존, 중복 요청, 파괴 요청 실패 복구, 손상 파일 보존 확인 |
| 툴바 | Node VM에서 실제 JS 검사. Headless Chrome 157에서 실제 web.html 핀 두 번 클릭으로 aria-pressed true → false → true, X 클릭으로 close 전달. Tauri IPC는 대역 사용 |
| 프로젝트 검사 | npm test (Rust 270, UI 200), npm run check (Clippy), cargo fmt --check, npm run dev:build (macOS ARM64) 통과 |
| 바이너리 출처 | npm run dev:info 및 scripts/agent-gibbon-dev --instance-info로 dev-eb219214c20f55c0e8875503, 1bbb 워크트리의 src-tauri 확인. 앱 프로세스 및 메모는 시작하지 않음 |

macOS·Windows 실제 OS 닫기, 네이티브 핀 전환, 원격 child 제거, 앱 재시작과 업데이트 설치는 실기기 미검증이다. 상태 전이 테스트의 Destroyed는 주입 이벤트다. Tauri 2.12.2 및 tauri-runtime-wry의 설치 소스에서 destroy의 이벤트 큐 전달과 호스트 종료 시 자식 등록 해제를 확인했다. 디자인과 시안의 외형·배치는 기존 기준을 따른다.

#184 후속 목록 UI에서는 살아 있는 웹 창의 조회에 기존 web::entries를 사용할 수 있다. CLI close는 해당 창을 숨기므로 종료 동작으로 재사용하지 않는다. 닫은 웹 ID를 의도적으로 다시 생성하려면 web 명령을 사용한다.
