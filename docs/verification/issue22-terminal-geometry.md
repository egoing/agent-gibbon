# #22 창 위치·크기 공용 저장과 터미널 PTY

열려 있던 창을 재시작 때 복원하는 경로와 닫아 둔 터미널을 목록에서 다시 여는 경로는 서로 다른 시점의 상태를 사용한다.

| 동작 | 이전 | 현재 |
|---|---|---|
| 열린 창 재시작 | 공용 `.session-windows.json`의 `windows` | 같은 기록에서 물리 위치·크기와 가시성·최소화·핀 등 복원 |
| 터미널 이동·리사이즈 | 공용 체크포인트와 별도로 터미널별 JSON 쓰기 | 다른 창과 같은 공용 체크포인트. 개별 이동 이벤트에서 터미널 JSON 쓰기 없음 |
| 터미널 종료 후 목록 재열기 | 터미널 JSON의 마지막 bounds | 공용 파일의 `closed_geometry`에서 종료 직전 좌표를 읽어 새 창에 적용 |
| 기존 기록으로 재열기 | 터미널 JSON의 bounds 및 Windows 물리 원점 표시 | 공용 닫힘 기록이 없으면 기존 형식 그대로 사용 |

공용 체크포인트는 약 1초 간격으로 수집하고, 실제 직렬화 바이트가 달라졌을 때만 같은 디렉터리의 임시 파일을 교체한다. 닫기 요청은 stash가 소유한 임시 배치를 먼저 해제하고, 창을 파괴하기 전에 마지막 위치와 클라이언트 크기를 읽는다. 네이티브 창 파괴에 성공하면 PTY 감독 작업에 종료를 통지하고 공용 저널에 좌표를 저장한다. 창 닫기는 현재 저널에서 해당 열린 창만 제외하고 나머지 창의 URL·펼침·표시 상태 등은 보존한다. 닫힌 창은 자동으로 재생성하지 않는다. 창을 다시 열면 다음 체크포인트부터 열린 창으로 기록하고, 목록 삭제 시 닫힌 좌표도 제거한다. 수집 도중 닫기/재열기가 먼저 끝나면 이전 수집 결과를 폐기한다.

닫힌 위치는 macOS의 논리 원점 및 크기, Windows의 물리 원점 및 논리 클라이언트 크기를 유지한다. 저널 손상으로 저장이 중지됐거나 첫 완전한 체크포인트가 아직 없으면 터미널별 기존 좌표에 닫기 시 한 번 기록한다. 첫 체크포인트 전 닫은 창은 첫 정상 체크포인트에도 포함한다. 강제 종료가 체크포인트보다 앞서면 가장 최근의 이동·재열기가 남지 않을 수 있다.

작업 경로·제목·복원 계획은 터미널별 기록에 남는다. 터미널별 저장 실패는 동일값을 명시적으로 다시 선택하면 재시도하고, 값이 같은 주기적 관측은 쓰기를 유발하지 않는다. PTY의 셀 수는 시작 시 성공한 크기부터 비교하고, 대기 중인 전송이 끝나면 최신 셀을 확인한다. 동일 셀 100회 재측정에서 중복 호출 101→0이라는 이전 JS 검증은 이 경로에 해당한다. 앞선 터미널별 저장 병합 시안에서 측정한 파일 쓰기 240→1·960→4 수치는 이번 공용 저널의 측정값이 아니다.

## 검증 범위

- 임시 디렉터리에 v1 열린 창 기록을 써서 닫기→재로드→목록 재열기 상태 전환→재로드→삭제를 확인한다. 뒤늦은 체크포인트 폐기, 다른 창의 URL 보존, 물리 원점 표시·분수 크기, 첫 체크포인트 전 닫기, 쓰기 실패 시 이전 유효 파일 보존과 후속 체크포인트 재시도를 검사한다.
- 텍스트·이미지·캡처·웹·터미널을 대표하는 다섯 열린 항목을 같은 체크포인트에 넣고 최종 크기와 같은 상태의 쓰기 생략을 검사한다. 파일·직렬화·저널 상태 전환은 실제 코드이고, 창 상태 입력은 합성 fixture다.
