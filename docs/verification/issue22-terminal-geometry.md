# 터미널 창 기하 저장과 PTY 크기 전송 (#22)

기준 main `22dc7de7309f8d47772bb0cf1f2c88768f742ef8`. macOS arm64, Rust/Cargo 1.91.1, Node 24.21.0, pnpm 11.25.0. 워크트리 `/Users/egoinglee/.codex/worktrees/a412/agent-gibbon`, 개발 ID `dev-5fd90bb0c7b74f844f0a2dad`. 기존 앱·사용자 메모·작업 폴더·실행 중인 PTY는 사용하지 않았다.

## 파일 저장의 경계

창 이동/리사이즈 이벤트에서 위치·안쪽 크기·배율을 읽고 메모리를 먼저 바꾼다. Windows는 물리 원점, 그 외는 논리 원점이며 크기는 논리 단위를 유지한다. stash 소유 창의 임시 기하는 제외한다.

같은 terminal JSON을 쓰는 경로는 창 생성, 기하, 작업 폴더 선택 및 현재 경로 갱신, 제목, 복원 명령, 자동 복원 여부, 경로 갱신 시각과 목록 삭제다. 기하 작업자는 ID별 기한만 예약하고, 쓰기 차례가 왔을 때 최신 레코드를 읽는다. 모든 쓰기와 삭제는 같은 I/O 잠금을 사용한다. 잠금 순서는 I/O → 메모리이며, 이벤트는 메모리 잠금만 쓴다. 디스크 작업 중에는 메모리 잠금을 풀고 같은 디렉터리의 임시 파일을 완성한 뒤 교체한다. 장시간 드래그에서도 첫 dirty 시점부터 120ms 단위로 진행한다. 파일 또는 OS 자체가 무한정 응답하지 않는 경우까지 종료 시간을 보장하지는 않는다.

핀·숨김·세션 체크포인트와 별도 저장되는 마지막 명령은 이 작업자가 쓰지 않는다. 기존 세션 검사와 프로세스 종료 정책은 변경하지 않는다. 마지막 기하·제목·작업 경로·복원 계획 등 terminal JSON의 필드는 같은 레코드에서 저장한다. 앱의 정상 종료 경로에서 마지막 기록을 flush하고 작업자를 기다린다. 작업자는 Tauri나 메인 스레드 콜백을 호출하지 않는다. 강제 종료·전원 손실에서 미저장 구간의 복구나 fsync 내구성을 보장하지 않는다.

## 임시 파일 실측

다음 값은 사용자 저장소나 실행 중인 PTY를 사용하지 않은 macOS 합성 burst의 최종 실행값이다. ID별로 x=i, y=−i, 너비=640+i, 높이=400+i를 i=0..239에 대해 차례로 제공했다. 생성 쓰기를 제외하고, 기준은 같은 main의 Terminal 타입과 기존 save 함수를 추출하여 실제로 기록했다. 변경 후는 실제 Records::geometry를 호출하고 worker가 종료 flush를 마친 뒤 성공 쓰기를 셌다. 이벤트 루프 시간에는 변경 후의 백그라운드 flush가 포함되지 않는다. 비교값은 전체 저장 소요나 프레임 시간의 백분위가 아니다.

| 창 | 이벤트 | 기준 → 변경 후 성공 쓰기 | 호출자 이벤트 루프(µs) | 종료 후 파일 |
|---|---:|---:|---:|---|
| 1 | 240 | 240 → 1 | 57,186 → 431 | (239, −239, 879, 639) |
| 4 | 960 | 960 → 4 | 262,462 → 508 | 4개 모두 같은 최종값 |

백그라운드 테스트는 쓰기 직전 worker를 멈춘 채 같은 창·다른 창의 메모리 기하가 갱신됨을 확인했다. 최신 제목·cwd·복원 계획·물리 위치 표시가 남았고, 동기 편집이나 삭제 후 동일 ID 생성이 먼저 완료된 분기에서도 오래된 예약으로 파일을 다시 쓰지 않았다. 임시 저장 디렉터리를 차단해 실패 표시와 종료 시 한 번의 재시도(복구/지속 실패)를 검사했다. Unix에서 직렬화할 수 없는 합성 경로를 넣자 원래 위치의 유효 JSON은 byte 단위로 그대로였으며 부분 파일이 남지 않았다. 비동기 실패는 로컬 stderr 및 terminal inspect의 `metadata_save_failed`로 확인한다. 저장 차단 중 같은 값으로 명시 재시도해도 실패를 반환했고, 차단 해제 후 주기적 관측만으로는 재시도하지 않았으며 같은 값을 명시적으로 다시 선택하자 파일에 반영되고 실패 표시도 해제됐다. 활성 변경이 없으면 무한 재시도하지 않는다.

## 셀 크기 검증

실제 `ui/terminal.js`를 VM에 로드하고 시작·resize Promise를 지연시켰다. 기준 구현은 시작 직후와 이후 같은 80×24를 100회 측정했을 때 101번 호출했다. 변경 후 같은 조건에서 추가 resize는 0회, 다른 셀(81×24)로 바꾸면 1회였다. 시작 중 변경, 대기 중 여러 차례 변경·원래 셀로 복귀, 실패 후 최신 셀로 진행, 같은 셀의 제한된 자동 재시도와 후속 측정, 시작 실패 후 재시작, 숨김 복원과 글자 크기 변경을 확인했다. 시작 성공은 실제 Rust에서 해당 크기로 openpty가 성공한 뒤 반환하는 응답을 기준으로 삼는다.

`scripts/terminal-surface-smoke.mjs`: 독립 headless Chromium에서 실제 xterm + 모의 native IPC를 사용. 3개 viewport × 3개 테마 × 1/2배 디바이스 배율, 18개 조합 통과. 폰트 4단계 순환, 마지막 시작/resize 요청의 행·열과 렌더러 행·열 비교 포함. 화면 모양을 변경하지 않아 기존 [시안](../design/terminal-capture-surface.png)을 유지한다.

## 실행 방법

- `pnpm install --offline --frozen-lockfile`, `npm run test:ui`: UI 검사 203개 통과.
- `node scripts/build.mjs cargo test --manifest-path src-tauri/Cargo.toml`: Rust 검사 272개 통과. 기본 제외된 기하 계측은 같은 명령 끝에 `measure_geometry_burst -- --ignored --nocapture`를 붙여 별도 실행했다.
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`, `npm run check`, `npm run dev:build`. 개발 실행 파일의 `./scripts/agent-gibbon-dev --instance-info`는 바이너리 출처 확인이며 실행 중인 서버나 GUI 확인이 아니다.
- 기존 `scripts/terminal-surface-smoke.mjs`는 독립 Chrome headless 프로필로 실행했다. 프런트엔드 검사와 파일/스레드 검사의 근거를 분리한다.

## 미검증

실제 Retina·혼합 배율·다중 모니터 간 이동, 동시에 여러 물리 창 드래그, 실제 앱의 핀·숨김·종료/재시작 및 OS PTY 화면 셀 일치는 확인하지 않았다. headless 배율 변경은 물리 모니터 변경과 다르다. 파일 fixture의 시간에는 네이티브 이벤트 전달·창 조회·렌더링이 포함되지 않으므로 실제 드래그 속도 개선 수치로 사용하지 않는다. Windows·Intel 빌드와 설치·배포도 실행하지 않았다.
