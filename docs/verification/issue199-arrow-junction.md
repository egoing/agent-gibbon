## 수정과 검사

제품의 기본 관계선과 연결 미리보기가 같은 밑변 기준 계산을 사용한다. 방향 표시가 있는 끝점에서 화살촉 길이만큼 곡선 종단을 안쪽에 두고, 남은 간격으로 절반 길이의 제어점을 계산한다. SVG 마커 기준점은 밑변 중앙이다. 기본 크기로 들어가지 않는 경우만 선을 위한 최대 1 CSS px(아주 좁으면 간격의 절반)를 남기고 한쪽 또는 양쪽 화살촉을 비례 축소한다. 중간 레이블은 바뀐 곡선의 t=0.5에 놓인다.

- 22dc7de 원본과 로컬 수정본 각각에서 제품 Rust의 Rect·curve·frame·local_points 정의를 추출해 rustc로 실행하고 각 checkout의 HTML/CSS/JS를 Chromium 139.0.7258.5에서 열었다. 메모·크기·배율은 합성 입력이다.
- 각 버전에서 252회 대조했다. 네 포트 × 세 배율(1·1.25·2) × 세 화살표 모드 × 일곱 배치(정렬/간격 80, 대각선/간격 45·25·8·1·0, 완전 접촉/같은 포트)다. 별도 음수 간격 입력에서는 Rust가 겹침으로 선을 생략했다. 같은 페이지에서 방향·거리·모드·레이블 유무를 바꿨다.
- 각 화살촉의 꼭짓점 복원, 양 끝 밑변과 접선 방향, 선 제어점의 단조 순서와 양 끝 범위, 원래 화살표 없음 경로, 레이블 중심과 실제 경로 절반 길이(오차 0.03 물리 px 미만)를 대조했다. 양방향에서 머리끼리 역전하거나 곡선이 되감기는 경우는 없었다.
- 각 배율·포트에서 같은 관계를 표시한 뷰포트를 512×512에서 320×320 CSS px로 변경하고 도착점을 화면 변에 놓았다. 12회 모두 내부 렌더와 잘라낸 영역의 잉크 경계가 일치했다. 꼭짓점부터 12 CSS px까지 삼각형 내부가 유지됐고 알파 차이의 합은 기준 영역 알파 합 대비 최대 0.066%였다. 가장자리 안티앨리어싱 때문에 전체 RGBA 바이트 일치 검사는 통과하지 않았다.
- UI 전체 201개와 관계·미리보기 집중 검사 10개, 전용 개발 빌드와 로컬 바이너리의 인스턴스 정보 조회를 통과했다. 두 SVG 시안을 PNG로 렌더하고 시각 확인했다.
