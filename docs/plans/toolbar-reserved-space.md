# 모든 메모창의 툴바 전용 행

## 요구사항

- 텍스트, 이미지·캡처, 터미널, 웹 창 모두 본문 위에 툴바 전용 행을 확보한다.
- 툴바 펼침 상태는 제목 없이 해당 창에서 지원하는 도구 버튼을 표시한다.
- 툴바 접힘 상태는 제목, 닫기, 펼치기 버튼을 표시한다.
- 두 상태 모두 본문을 계속 표시한다. 이는 대화에서 제시한 해석에 따라 진행하는 기준이다.
- 포인터가 벗어나도 전용 행의 공간과 접힌 상태의 컨트롤을 유지한다.
- 기존 메모 접기 상태와 툴바 접기를 통합하고 전체 창 숨김은 유지한다.
- 기존 창 위치, 사용자 포커스, 숨김 상태와 유형별 닫기 동작을 보존한다.

## 조사 결과와 구현 계획

- `ui/style.css`의 absolute 툴바와 이미지 전체 inset 레이아웃이 본문과 겹친다. 공통 상단 행과 본문 영역을 분리한다.
- `ui/app.js`의 본문 크기 측정에서 툴바를 제거하고 있어 새 행 높이를 포함하도록 보정한다.
- `ui/terminal.html`과 `ui/terminal.css`의 제목 행을 같은 상태 규칙으로 통합하고 PTY 가용 크기를 다시 계산한다.
- 웹 Welcome 및 외부 WebView의 실제 창 구조를 조사해 외부 콘텐츠와 툴바의 공간을 분리한다. 웹 핀·종료 동작은 #119와 경계를 확인한다.
- 공통 디자인 기준은 [디자인 시스템](../design-system.md)에 반영하고 관련 SVG·PNG 시안을 갱신한다.
- 행 높이와 초기 펼침 상태는 기존 클릭 영역과 사용성을 확인한 뒤 결정한다.

## 완료 기준과 검증 계획

- 모든 유형에서 본문 첫 줄이나 이미지가 툴바와 겹치지 않는다.
- 툴바를 접으면 본문이 숨겨지고 제목·닫기·펼치기만 남으며 창 높이는 32px가 된다.
- 좁은 창, 긴 제목, 키보드 탐색, 편집, 이미지 비율, 터미널 resize와 웹 콘텐츠 영역을 확인한다.
- 기존 전체 접어두기·숨김·복원과 사용자 포커스를 회귀 확인한다.
- 관련 UI 회귀 테스트, Rust 테스트·Rustfmt·Clippy, 개발 빌드를 실행한다.
- 개발 인스턴스 ID와 실제 PID·메모 ID를 대조한 뒤 CLI와 실제 창을 검증한다.
- 플랫폼 간 영향이 있으므로 승인된 커밋을 push한 뒤 전체 플랫폼 workflow 검사를 요청한다.
