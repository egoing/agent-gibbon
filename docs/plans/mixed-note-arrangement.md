# 웹·캡처 메모 정렬 누락 수정 계획

기준: 2026-11-15, origin/main 307f7fde87874763e6c5c5009fd903ae2a6949c0.

사용자 제보는 웹·캡처 메모가 측면·타일 정렬에서 빠진다는 것이다. 실행 재현과 코드 추론은 분리한다. 실제 기능은 오른쪽 제스처의 오른쪽 정렬, 위 제스처의 바둑판 정렬이며 왼쪽은 취소다.

- [x] 지침·최신 main·명령 매핑·최근 종료 이슈 확인
- [x] 유형별 대상 수집·크기·생성 순서·숨김·수동 제외·진입 전환 코드 조사
- [x] 웹·터미널 최소 수정과 두 정렬·이미지 비율·크기의 계산 회귀 검사
- [ ] 캡처 누락 자체 native 재현·두 정렬·실제 5초 취소/숨김 회귀 (입력 소유권·CUA 앱 식별 제한)
- [x] 디자인 시스템·SVG/PNG 시안과 검증 출처 갱신
- [x] 관련 검사·개발 빌드·전용 인스턴스 CLI fixture 확인
- [ ] native GUI 확인 완료 (미검증 범위는 검증 기록 참조)
- [x] 결과 제출 후 close 호출로 제품 커밋·push 승인 확보
- [ ] 캡처 재현·native 완료 기준 충족 후 병합·이슈 종료

범위 밖: 일반 열기 배치 정책 변경, 다른 작업의 미커밋 코드, 사용자 기존 창 변경, 외부 웹 탐색·실제 셸 실행, 전체 플랫폼 CI·릴리스.

현재 코드 확인: managed_windows는 웹 host를 합치지만 arrange는 memo_id_from_window로 웹·터미널을 제외한다. 캡처는 note-image label로 이 조건을 통과하므로 동일 원인이라고 단정하지 않는다. auto_layout_excluded는 명시적 arrange에서 검사하지 않는다.

검증 결과와 제한: [#191 기록](../verification/issue191-mixed-arrangement.md). 제품 변경은 미커밋이며 실제 캡처 누락·undo는 미검증이다.

close 호출: 커밋·push 권한을 받아 이번 변경을 보존한다. 미완료 원래 요구사항이 있어 병합·이슈 종료·워크트리 제거는 보류한다.
