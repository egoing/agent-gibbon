# 모니터 환경 변경 시 창 배치 정책·검증 계획 — #190

## 문제와 목표

외부 모니터 분리·해상도/배율·작업 영역 변화 뒤 메모가 화면 밖에 남거나 서로 가려 제어할 수 없으면 기존 작업을 이어가기 어렵다. 사용자의 정상 배치를 최대한 보존하면서 접근 불가 창만 최소 보정한다.

이 문서는 2026-11-15 작업 20번 사용자 합의와 검증 계획을 기록한다. 첫 계획 커밋에는 이 문서만 포함했다. 이후 사용자가 팀장 채팅에서 `20 병합승인`을 명시하여, 검증된 제품 변경과 디자인·증거 자료를 같은 PR에 반영한다. 관련 이슈: #190.

## 합의한 정책

- 정상적으로 사용할 수 있는 창은 위치·크기를 유지한다. 접근 불가 창만 남은 작업 영역으로 이동하며 과대 창은 필요한 만큼 임시 축소한다.
- 피난한 창끼리 툴바를 가리면 해당 창만 국소 분산한다. 정상 창과 사용자 수동 배치는 최대한 보존한다. 이미지 원본·비율을 유지한다.
- 원래 배치와 임시 피난 배치를 구분해 저장한다. 모니터가 돌아오면 원래 위치·크기로 복귀하되, 분리 중 직접 이동·resize한 창은 사용자의 최신 배치를 우선한다.
- 숨긴 창을 환경 변경만으로 표시하지 않는다. 핀·접힘·최소화·수동배치 제외·초안·포커스·살아 있는 세션을 보존한다.
- 접힘의 펼친 크기·작업 영역 확대 전 복원 정보를 임시 크기로 덮지 않는다. 방향 정렬의 5초 취소도 기존 모니터 복귀 관계를 복원한다.
- 작업 영역은 메뉴 막대·Dock·작업표시줄을 제외한다. 여러 화면의 연속 작업 영역 안에서 정상적으로 쓰는 창은 유지한다.

## 구현·통합 계획

1. 로컬 session checkpoint에 원래/임시 기하·화면 정보와 별도의 확대 복원 상태를 선택 필드로 추가하고 기존 journal 하위호환을 유지한다.
2. 현재 화면 목록·작업 영역·배율 변화가 안정된 뒤 보정한다. 논리 크기와 물리 데스크톱 원점을 구분하며 화면 조회 실패/화면0개에서는 유효한 저장 상태를 보존한다.
3. 직접 drag/resize·워프·방향 정렬과 자동 이동을 구분한다. 접어두기·등장/측정·캡처·마우스 누름·업데이트 동결과 경합하지 않도록 보류한다.
4. 모니터 이름만으로 재연결을 단정하지 않는다. 식별값·배치·배율이 달라 동일 화면을 확정할 수 없으면 안전 배치를 유지한다.
5. 텍스트/이미지·PTY·웹의 기존 resize 경로와 관계선 등 후속 기능의 좌표를 검토한다. 다른 이슈의 성능·플랫폼 완료를 대신 주장하지 않는다.
6. UI 동작 기준은 디자인 시스템과 설명 SVG/PNG, 실행 근거는 검증 기록으로 함께 관리한다. 사용자 시나리오와 실제 관찰/inspect 증거를 구분한다.

초기 구현 후보는 화면 조회250ms·동일 구성750ms 유지, 국소 충돌 탐색량 제한이다. 이는 측정 후 조정 가능한 구현값이며 물리 플랫폼 검증을 대신하지 않는다.

## 완료 기준·검증 계획

| 기준 | 검증 |
|---|---|
| 정상 창 불변·접근 불가 창 구제 | 음수좌표·혼합 배율·인접 화면 걸침·작업 영역 변경·큰 창·과밀 기하 테스트 및 실제 분리 |
| 재연결 원복·직접 조작 우선 | 분리→C만 직접 이동/resize→재연결 후 B원복/C최신 배치 확인 |
| 저장 정보 보존 | 원래/임시 배치 직렬화·부재 상태 재시작·기존 journal·손상 상태/조회 실패 보호 |
| 상태/유형 보존 | 숨김·접힘·핀·최소화·확대 원복·정렬 취소·이미지/PTY/웹의 전환·초안/IME |
| 이벤트 경합·플랫폼 차이 | 연속 이벤트 안정화, 도킹·덮개·잠자기·회전·주화면 변경, macOS/Windows/Intel 구분 |
| 출처 확인 | worktree root/id/binary·실제PID·inspect.instance/id/고유본문·기하·해시·명령과 결과 기록 |

모든 표시 창의 툴바·크기 조절 영역 접근과 사용자 작업 보존을 목표로 한다. 물리적 화면 용량을 넘으면 임의 종료/숨김을 하지 않고 기존 개별 접근 수단을 유지하며 한계를 명시한다. 메모 관리에 포함되지 않는 웹 창의 복구 경로도 구분한다.

## 현재 확인 범위와 남은 일

구현 검증 기준은 main `307f7fde87874763e6c5c5009fd903ae2a6949c0` 위의 미커밋 제품 변경이다. 컬러 #189·방향 정렬 #173·툴바 확대 #180을 포함한 기준에서 작업했다. 계획 커밋과 제품 변경 커밋을 분리한다.

- Rust246개·UI189개, Clippy all-targets `-D warnings`, 개발 debug 빌드·Rustfmt·diff check를 확인했다. 이 검사들은 미커밋 구현에 대한 로컬 결과이며 계획 PR의 제품 실행 결과가 아니다.
- 사용자 실제 분리·재연결에서 A 위치/크기 유지, B 원복, C 직접 이동 우선, H 숨김을 확인했다. 분리 중 남은 화면 논리 해상도도 함께 바뀌어 단일 변수 실험은 아니다.
- 사용자가 성공을 보고했지만 C 크기 수치는 계속720×460이었다. 직접 resize·그 이후 재연결 우선은 미실증으로 남긴다.
- 준비 중 CLI --serve의 초기 foreground 대상 누락을 발견해 초기 대상 캡처/Ready 마무리를 보강했다. 시작 중 일시 활성화는 남아 있고 안정 후 기존 앱으로 복귀하는 범위만 확인했다. 제3앱 선택·명시 클릭·최소화 GUI는 별도 검증이 필요하다.
- 실제 과대 창 축소/해상도·배율 전환, 혼합 DPI·Windows/Intel, 이미지/실행 PTY/외부 웹·초안/IME·접힘/확대/정렬 취소의 물리 통합은 미완료다. 저장 fixture를 이 실제 시험의 통과로 간주하지 않는다.

전체 확신도 Conf3 / 위험도 Medium. 완료 기준별 미실증은 열린 상태로 유지한다. 사용자 `20 병합승인`에 따라 제품 커밋·push·PR 병합과 로컬 main 동기화를 진행하며 공개 배포는 포함하지 않는다. 사용자가 시험 중인 앱과 최신 메모 배치는 유지한다.
