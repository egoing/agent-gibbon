# #15 · 취소한 미저장 초안 복구 계획

기준: main 22dc7de. #174 후속 자동저장의 현재 계약을 기준으로 확인한다. 저장 실패 후 Feedback의 변경 취소로 버린 사용자 입력이 남아 있는지 독립 브라우저에서 먼저 재현한다. 이미 충족되면 제품을 바꾸지 않는다.

- 확인: 실제 Milkdown/Feedback에서 입력 → 저장 실패 → 변경 취소 → undo를 관찰한다. Esc의 저장 후 숨기기와 구분한다.
- 범위: 메모 WebView마다 최근 취소 초안 한 개만 메모리에 보관한다. 복구는 명시적인 보조 버튼에서만 실행한다. 새 입력을 보호하고 외부 revision에서 이전 undo 이력을 재생하지 않는다.
- 원문 보호: 현재 원문에 대한 undo와 초안이 처음 기반한 저장 revision을 구분한다. 복구 전에 외부 갱신이 있었다면 자동저장을 막고 명시적 재시도도 기존 CAS·연결 파일 충돌 검사를 거치게 한다.
- 검증: 독립 브라우저에서 정상·충돌·연속 입력·IME 합성 이벤트·숨김·키보드·진행 중 작업을 확인한다. 디자인 시스템과 연결 시안을 실제 결과와 맞춘다. 네이티브 입력·포커스·설치 앱은 건드리지 않는다.
- 인계: 제품 변경은 별도의 로컬 검토 패치로만 보존한다. 원격 Draft에는 계획만 올리며 병합·이슈 종료·배포는 별도 범위다.

## #183 서식 명칭과 함께 검토

선택 서식 메뉴의 ‘큰제목’, ‘작은제목’, ‘코드’를 적용한 초안을 취소·복구하는 흐름을 같은 편집기에서 검증한다. 최신 원문과 충돌한 초안은 복구하거나 서식을 바꿔도 원래 revision으로만 저장을 시도해야 한다. 각 이슈의 개별 검토본은 보존하고 두 변경을 합한 패치를 별도로 검토한다. [결합 검증 기록](../verification/issue183-15-milkdown.md).
