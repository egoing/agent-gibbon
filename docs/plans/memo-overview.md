# 왼쪽 정렬과 메모 모아보기 · #217

작업 37(두루)의 시작 커밋은 `16d1b2a`다. 사용자 확정 동작은 위 제스처로 진입할 때 현재 배치를 보관하고, 닫을 때 각 메모의 진입 직전 위치와 크기를 그대로 복원하는 것이다.

| 입력 | 전이 | 메모의 위치와 크기 |
|---|---|---|
| 왼쪽 제스처 | 일반 보기에서 왼쪽 정렬 | 생성 순서와 기존 정렬 크기를 유지하며 열마다 왼쪽 가장자리에 맞춤 |
| 위쪽 제스처 | 일반 → 메모 모아보기 | 보이는 메모의 진입 프레임을 한 번만 보관. 배경과 하단 두 버튼을 표시 |
| 자동 정렬 | 메모 모아보기 유지 | 현재 대상에만 바둑판 계산 적용. 하단 조작 영역 확보 |
| 수동 이동 | 메모 모아보기 유지 | 다음 명시적 조작까지 이동한 위치 유지 |
| 닫기 | 메모 전용 → 일반 보기 | 최초 프레임 복원. 해당 세션의 배경과 버튼 숨김 |
| 다시 진입 | 새 보기 세션 | 그 시점의 새 프레임을 보관. 이전 세션에서 지연된 버튼 입력 무시 |

상태 전이 [SVG](../design/memo-overview.svg) · [PNG](../design/memo-overview.png). 단색 배경과 버튼 치수는 시안 구현값이다. 기존 정렬의 크기·접힘·생성 순서·숨김 제외 규칙은 [디자인 시스템](../design-system.md)의 세 보조키 방향 정리 절을 따른다.

## 통합 범위

- `layout.rs`와 하위 모듈에서 명시 정렬 대상 선정·혼합 유형별 크기·창 이동을 공유한다. 보기 세션은 메모 본문·선택·PTY·웹 child를 재생성하지 않는다.
- 36의 입력 안정화가 확정된 다음 `stash.rs`의 방향 분기·숨김 복원 예약·보조 창 분류와 안내 자산·대체 텍스트를 연결한다.
- 명령 등록과 시스템 창 닫기 이벤트는 `main.rs`에서 조율한다. 디자인 시스템은 방향 정리 절과 연결 시안만 변경한다.
- 실제 macOS 검증은 예약된 순번에 전용 인스턴스의 inspect와 PID·창 제목을 대조하고 진행한다. 혼합 메모·미니마이즈·핀·접힘·초안·PTY·웹 child·포커스·재진입·버튼 실패 회복을 확인한다.

## 공유 구간과 대기 조건

- 작업 36과 공유하는 `stash.rs`의 `sample_pointer`, `arrange_direction`, `snapshot_candidate`, `install` 및 guide SVG/PNG·안내 JS는 팀장이 전달하는 안정화 기준을 기다린다.
- `main.rs`는 `generate_handler!`의 기존 `layout::undo_arrangement` 바로 다음 한 줄이 메모 보기 버튼 명령 등록 지점이다. 핀 해제 터미널의 blur 처리는 보기 세션 중 사용자 조작 시 관찰할 항목이다.
- `docs/design-system.md`는 ‘세 보조키 방향 정리’ 절과 ‘정렬 불투명·복원 눈 아이콘’의 이전 상태 설명만 대상으로 한다.

## 통합 전 확인

음수 좌표·서로 다른 창 너비의 왼쪽 정렬, 혼합 창 크기 제한, 닫기 실패 후 재시도·재진입 세션 구분, 버튼 요청 중복·지연 응답을 검사했다. Rust 305개 통과·1개 기존 ignored, UI 217개 통과. Chromium에서 180×68 버튼 창의 키보드 포커스·Enter 순서·가로 넘침과 밝음/어두움 배경을 확인했다. 버튼 호출은 대역으로 검사했다.
