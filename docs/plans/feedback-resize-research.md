# 피드백 바 크기 조절 가능성 조사 계획

기준: 2026-11-14, origin/main `53ab3a710fb54f4702de2499fdc22b9dd8506087`.
작업 루트: `/Users/egoinglee/.codex/worktrees/6eec/agent-gibbon`.
현황판 7번 독립 조사이며 제품 구현은 포함하지 않는다.

## 조사 순서

1. 디자인 시스템과 연결된 Feedback·통합 테두리 시안, 현재 native 창 생성·배치·입력·크기 상태 경로를 확인한다.
2. 설치된 Tauri/Tao/Wry 버전·소스와 최신 공식 문서를 대조하여 부모 메모 resize 전달의 가능성과 플랫폼 제약을 정리한다.
3. 메모 전체 조절과 Feedback 자체 높이 조절을 구분하고 2~3개 대안의 장단점과 권장안을 제안한다.
4. 자동 높이 폴링·위아래 부착·DPI·이미지 비율·접힘·화면 경계·입력 충돌·초안/포커스·IPC 소유권·편집 높이 후속 작업의 충돌을 검토한다.
5. 조사 결과 문서에 공식 출처·조회일·후속 완료 기준과 실환경 검증 계획을 남기고 팀장에게 결과와 한계를 보고한다.

## 완료 기준과 권한 경계

- 코드상 가능성과 실제 drag 입증을 구분한다. 정적 조사로 충분하면 GUI·앱을 실행하지 않고 실동작 미검증을 명시한다.
- 결과 문서는 `docs/research/feedback-resize.md`에 보존한다. 확정 규칙이나 시안은 변경하지 않는다.
- 첫 계획 커밋·push·Draft PR 준비만 사전 승인 범위다. 최종 조사 결과 커밋·push·병합은 승인 대기한다.
- 다른 워크트리·사용자 앱·공유 index·빌드 출력은 변경하지 않는다. 전체 플랫폼 CI·릴리스·배포는 실행하지 않는다.
- 디자인 기준: [디자인 시스템](../design-system.md), [피드백 시안](../design/feedback-drag.svg), [활성 테두리 시안](../design/memo-focus.svg).

## 사용자 후속 승인 — 2026-11-14

- 사용자가 Feedback을 메모 내부 하단으로 옮기고 창 크기를 유지하는 구현을 지시했다. 조사만 진행하던 범위를 이 구현까지 확장한다.
- 창 크기 유지의 적용 범위는 Feedback 표시·숨김·안내 변경이다. 별도 편집 진입 높이 정책(6번)은 독립적으로 유지하며 이 브랜치에 포함하지 않는다.
- 별도 native companion 생성·배치·포커스/투명도 동기화를 제거하고 같은 viewport 안의 footer·본문 flex·기존 resize·초안/버튼 접근을 검증한다.
- 디자인 시스템과 연결 SVG/PNG를 갱신한다. 최종 구현 커밋·push·병합은 여전히 승인 대기한다.
