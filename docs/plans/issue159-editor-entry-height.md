# #159 편집 진입 높이 확보 계획

## 목표와 경계
텍스트 메모의 편집을 시작할 때 현재 높이가 자동 높이 상한의 절반보다 작으면 한 번만 확대한다. 자동 상한 420 논리 px를 소유한 sizing 정책을 공유하며 210을 별도 상수로 복제하지 않는다. 이미 큰 창·이미지·웹·터미널은 변경하지 않는다. Feedback resize 조사는 별도 작업이다.

## 구현 방향
- 프론트엔드의 실제 편집 진입에 native 명령을 연결한다. 폴링·숨김 복원·초안 갱신으로 반복 확대하지 않는다.
- native 크기 조절은 현재 너비와 가능한 좌상단을 유지하고 화면 하단에 공간이 없으면 필요한 만큼만 위로 이동한다. 자동 배치와 다른 창은 변경하지 않는다.
- 진입 시 진행 중인 등장/배치 애니메이션과 접힘 상태를 확인하고, 영역 새 메모의 초기 편집도 검토한다.
- 영구 min-height나 사용자 수동 resize 제한을 추가하지 않는다. 저장·취소·충돌 처리와 초안 계약을 유지한다.
- 디자인 시스템에 확정 동작과 적용 상태를 기록하고 별도 SVG/PNG로 작은 창·큰 창·경계 동작을 설명한다.

## 검증 계획
- Rust 기하 정책 테스트: 임계 미만/같음/초과, 화면 경계·음수 좌표·DPI.
- UI 회귀: 진입당 한 번 호출, 저장·취소·초안·이미지 제외, 초기 편집.
- Rustfmt·Clippy·Rust/UI 테스트·개발 빌드.
- 본 워크트리 개발 CLI inspect의 instance/id/본문, debug 실행 경로/PID/native 창 제목 확인 후 작은 창과 큰 창 전후 크기·입력 접근·Feedback 연결 검증.
- 실제 macOS ARM64 검증과 Windows·Intel·혼합 DPI·전체 플랫폼 CI 미검증을 구분한다.
