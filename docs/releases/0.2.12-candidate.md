### 실기기 시험안과 출처

기존 설치 앱·다른 워크트리·main 개발 앱을 종료하거나 교체하지 않는다. [설치 보호 시험](../releases.md#설치-보호-실기기-시험)과 [체크리스트](../verification/issue102-live-checklist.md)에 따라 이전/후보를 `verification-updater` feature, 같은 별도 bundle ID/설치 경로·일회용 키·loopback 피드로 준비한다. 이전 기록은 현재 후보의 통과 근거가 아니다.

1. 팀장과 GUI/빌드/기기 사용 차례를 조율하고 미저장 작업과 실행 PTY를 확인한다. 모니터 설정·권한 변경은 별도 조율한다.
2. 정확한 루트·소스 SHA·후보 바이너리 해시·실행 파일 절대 경로/PID·인스턴스·메모 ID/고유 본문을 기록한다. 개발 검증은 `npm run dev:info`와 해당 루트 `scripts/agent-gibbon-dev inspect`의 instance/ID/본문을 대조한다. GUI 전 네이티브 창 제목/PID 또는 동일 고유 표식을 대조한다.
3. 검증 전용 데이터에서 읽기·미저장 편집·실행 PTY·숨김·접힘·핀·텍스트/이미지/웹 상태를 안정화해 기준을 기록한다. CLI 호출의 관찰 효과와 사용자 조작을 구분한다.
4. 피드 버전·실제 HTTP payload 해시·서명 manifest를 대조한 뒤 보호 보류·수동/자동 설치·재시작·실제 실행 버전과 전후 상태를 비교한다. 기본 300초 무입력과 단축 프로필을 구분한다.
5. 눈 아이콘·이동 불투명·연결 생성/저장/복원은 후보 전용 창에서 수동 확인한다. 기존 사용자 메모로 식별하지 않는다.
6. 이번에 만든 프로세스/피드/키만 정리하고 저장 상태를 보존한다. Windows/Intel/ARM64와 미실행 항목을 구분한다.
