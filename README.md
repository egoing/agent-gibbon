# Agent Gibbon

[English](README.en.md) · [홈페이지](https://agentgibbon.com/) · [다운로드](https://github.com/egoing/agent-gibbon/releases/latest) · [설치와 CLI 안내](https://agentgibbon.com/guide/)

에이전트가 CLI로 갱신하는 작은 플로팅 Markdown 메모. Tauri 2 + Rust + 시스템 WebView로 동작하며 웹 서버 없이 동작합니다. 공식 배포판은 Sentry로 앱 오류 진단 정보를 전송합니다. 개발·테스트 및 DSN 없이 빌드한 앱은 전송하지 않습니다. 메모는 로컬에 유지됩니다.

## 지원 기능

- ID로 구분하는 여러 프레임리스 메모 창, 본문 전체 드래그와 가장자리 크기 조절
- 창별 배경색 지정과 읽기 쉬운 흑백 글자색 자동 선택
- 본문 우측 aA·연필·복사·워프·핀·닫기 버튼, 제목바·하단바 없는 슬림 화면
- 메뉴 막대의 메모 아이콘에서 열린 메모를 앞으로 가져오거나 개별 메모 복원
- 메뉴 막대의 개별 메모 왼쪽 ✓는 현재 열린 창을 뜻합니다. 숨긴 창에는 체크가 없고, 접힌 창은 열린 창으로 표시합니다. 항목을 선택하면 기존처럼 해당 메모를 앞으로 가져오거나 복원하며, 체크된 항목을 다시 선택해도 숨기지 않습니다.
- 버튼과 크기 조절 가장자리를 제외한 창 전체를 드래그하여 이동, 복사 버튼으로 표시된 본문 전체 복사
- 내용에 맞춰 자동 크기 조절(가로 300 고정, 세로 48~420 논리 픽셀), 본문 12px 기본값과 14·16·18px 전환·여백 3px
- 체크박스 행은 목록 점·들여쓰기 없이 표시, 일반 목록은 기존 형식 유지
- `open`으로 앱 자동 실행과 표시, `update`로 부분 갱신, `close`로 숨기기
- 새 메모와 숨긴 메모를 열면 커서가 있는 모니터에서 커서와 12 논리 px 여백을 둔 가까운 위치에 완전 불투명하게 표시하고, 최소 1초 대기한 뒤 처음 움직인 마우스 방향을 실행: 오른쪽·왼쪽은 해당 화면 가장자리로 420ms cubic ease-out 이동, 위쪽은 접고 오른쪽 이동, 아래쪽은 현재 위치에서 X 버튼처럼 숨김
- 표시 당시 커서에서 우세 축으로 8 논리 px 이상 움직이면 방향을 한 번 확정합니다. 대기 중 선택도 기억하고 반전해도 바꾸지 않으며, 대각선의 두 축이 같으면 좌우를 우선합니다. 움직임이 없으면 1초 후에도 기다립니다. 위쪽 동작은 이미 접힌 노트를 펼치지 않고 이전 펼친 크기를 보존합니다. 목적지는 표시 시작 시 커서가 있던 모니터의 작업 영역이며 8px 여백을 둡니다. 명시적인 방향 이동은 다른 노트와 겹칠 수 있습니다.
- 이미 보이는 메모의 `open`과 내용 갱신에는 등장 이동을 반복하지 않음
- 이동 중 숨기면 목적지를 보존하고, 직접 드래그하면 자동 이동을 중단
- 갱신 시 포커스·위치·숨김 상태와 사용자가 지정한 크기 유지, 명시적인 `open`으로만 복원
- 한글, 표, 코드, 읽기 전용 체크리스트 Markdown 지원
- 원시 HTML은 텍스트로 처리하고 sanitizer로 정리; 이미지·링크 이동·외부 리소스 차단
- CLI는 stdout에 JSON 한 개를 반환; 오류는 `ok: false`와 종료 코드 1

기존 창의 자동 재배치, 사용자 답변, 계정, 클라우드는 지원 범위에 포함하지 않습니다. 앱과 기본 사용 스킬은 작업계획 등 특정 워크플로우를 강제하지 않습니다.

## 글자 크기와 편집

- `aA`를 누르면 **12 → 14 → 16 → 18 → 12px**로 순환합니다. 제목·코드·표도 비례해서 커집니다. 크기는 창별로 유지되며 CLI 갱신이나 숨기기로 초기화되지 않습니다.
- 연필 버튼으로 Markdown 원문을 편집하고 **저장** 또는 **⌘S / Ctrl+S**로 반영합니다. **취소 / Escape**는 편집을 취소합니다. 편집 중에는 텍스트 선택과 입력이 가능하며, 창을 숨겨도 저장하지 않은 초안은 유지됩니다.
- `--file 경로`로 연 메모는 저장할 때 원본 파일도 갱신합니다. `--markdown`이나 `--file -`로 입력한 메모는 앱 안에서만 변경합니다. 저장 대상은 편집 화면에 표시됩니다.
- 제목·상태·색상만 CLI로 갱신하면 파일 연결을 유지합니다. `--markdown`이나 표준입력으로 본문을 교체하면 파일 연결을 해제하고, 다른 `--file`로 교체하면 새 파일에 연결합니다. 원본 파일을 자동 감시하지는 않습니다.
- 편집 시작 후 CLI가 메모를 갱신했거나 원본 파일 내용이 달라졌다면 저장을 거부하고 초안을 유지합니다. 필요한 내용을 복사한 뒤 취소하고 최신 내용으로 다시 편집하세요. 파일이 외부에서 바뀐 경우 CLI의 `update --id ID --file 경로`로 다시 읽습니다.
- 파일 저장은 같은 디렉터리의 임시 파일을 완성한 뒤 교체합니다. 읽기 전용·삭제된 파일이나 검증 오류는 기존 메모를 변경하지 않습니다. 저장 순간 다른 프로그램이 동시에 파일을 쓰는 상황까지 잠그지는 않으므로 동시 편집은 피하세요.
- 앱을 완전히 종료하면 저장하지 않은 초안과 글자 크기는 초기화됩니다. 기존 버전에서 열었던 메모는 새 버전에서 `--file`로 다시 열어야 원본 파일과 연결됩니다.

## 접촉으로 닫기

- 이동·접기·닫기 접촉 단축키는 보조키를 누른 채 노트 밖에서 안으로 들어올 때만 실행됩니다. 커서가 이미 노트 위에 있을 때 키를 누르거나 놓았다가 다시 눌러도 실행하지 않습니다. 포커스된 노트에서는 접촉 단축키를 실행하지 않으며, 포커스를 잃어도 커서가 안에 머무는 동안 실행하지 않습니다. 화면 버튼은 그대로 사용할 수 있습니다.

- macOS에서 **Control + Option(Alt) + Command(Win)**을 모두 누른 채 포인터를 노트에 올리면 닫습니다. 다른 앱에 포커스가 있거나 노트가 접힌 상태에서도 동작합니다.
- 기존 닫기 버튼처럼 숨기며 본문·편집 초안을 유지합니다. 메뉴 막대나 CLI `open`으로 다시 열 수 있습니다.
- 세 키 조합은 Option 워프와 Control 접기보다 우선합니다.

## 접기와 펼치기

- macOS에서 Control을 누른 채 포인터를 메모 위에 올리면 접기·펼치기가 전환됩니다. 다른 앱에 포커스가 있어도 동작하며, 포인터를 밖으로 움직였다가 다시 접촉하면 재실행됩니다.
- 접촉 감지는 macOS의 앱 내부·외부 마우스 이동 이벤트에서 즉시 처리하고, 100ms 주기 확인을 보조로 유지합니다. 접힌 메모에만 사방 4 논리 px의 감지 여유를 주며, 창 크기와 클릭 영역은 바꾸지 않습니다. 서로 다른 배율의 모니터도 같은 데스크톱 논리 좌표로 비교합니다.
- 접힌 메모는 높이 12 논리 픽셀로 줄고 10px의 작은 제목과 오른쪽 펼치기 버튼만 표시합니다. 펼치면 이전 크기를 복원하며 본문·편집 초안·수동 크기·위치·핀을 유지합니다. 접힌 동안 내용 갱신은 메모를 펼치지 않습니다.

- 접힌 메모는 포인터가 밖에 있을 때 불투명도 80%로 표시하여 펼친 메모(50%)보다 선명하게 유지한다. 포인터를 올리거나 변경 알림이 진행 중이면 100%로 표시한다.

- 펼친 상태에는 접기 아이콘, 접힌 상태에는 펼치기 아이콘을 표시한다. 아이콘에 포인터를 올리면 Control + 포인터 접촉으로 접기·펼치기를 전환하는 단축키 안내가 툴팁으로 표시된다.

## 워프

- 좌우 화살표 아이콘을 누르거나 macOS에서 Alt(⌥ Option)를 누른 채 포인터를 노트에 올리면 현재 모니터의 반대편으로 이동한다. 노트 중심으로 좌우를 판정하고, 화면 가장자리에서 8px 간격과 처음 열린 세로 위치를 사용한다. 화면·크기가 바뀌면 작업 영역 안으로 위치를 제한한다.
- 크기·본문·편집 초안·고정·포커스를 유지한다. 다른 노트의 위치는 바꾸지 않으며 이동 목적지의 노트와 겹칠 수 있다. 노트가 화면보다 크면 이동하지 않고 오류를 표시한다.
- Alt 접촉은 다른 앱에 포커스가 있어도 동작한다. 이동 자체로 반복 실행되지 않으며, 포인터를 노트 밖으로 움직였다가 다시 들어오면 재실행된다.
- 실행 후 노트 하단에 12초 동안 단축키 안내가 표시된다. ‘닫기’는 이번 안내만 닫고, ‘다시 보지 않기’는 모든 노트에 적용되어 앱 재실행 후에도 유지된다. 숨긴 노트에는 워프를 실행하지 않는다.


## 빌드와 실행

Windows 개발·빌드 절차와 플랫폼 차이는 [Windows 안내](docs/windows.md)를 참고하세요.

macOS에서 Rust stable, Node.js/npm, Xcode Command Line Tools 및 macOS SDK가 필요합니다. CPU 아키텍처는 호스트 기본값을 사용합니다.

```sh
npm ci
npm run build
./scripts/agent-gibbon open --title '현재 작업' --status '진행 중' --file examples/progress.md
```

앱 번들: `src-tauri/target/release/bundle/macos/Agent Gibbon.app`

CLI 실행 파일: `src-tauri/target/release/agent-gibbon`

프로젝트의 `scripts/agent-gibbon`는 release 실행 파일을 우선 사용하고 없으면 debug 실행 파일을 사용합니다. 다른 디렉터리에서도 절대 경로로 호출할 수 있습니다. Apple 배포 서명·공증은 설정하지 않았습니다. 다운로드한 배포판은 macOS 보안 확인에서 차단될 수 있습니다.

```sh
# 워크트리별 개발 앱 (프론트엔드 서버 없이 Rust 변경 감시)
npm run dev
# 또는 실행 파일만 빌드한 뒤 CLI open으로 해당 개발 앱 시작
npm run dev:build
./scripts/agent-gibbon-dev open --id sample --markdown '이 워크트리의 메모'
./scripts/agent-gibbon-dev inspect --id sample
npm run dev:info
```

개발 실행과 `scripts/agent-gibbon-dev`는 실제 워크트리 절대 경로(심볼릭 링크 해소)의 SHA-256 앞 24자리로 같은 `dev-…` ID를 계산합니다. 호출한 현재 디렉터리나 브랜치 이름에는 의존하지 않습니다. 경로를 옮기면 ID도 달라집니다. 소켓과 중복 실행 잠금은 `/tmp/floatnote-{uid}-{개발ID}/`로 분리됩니다. 개발 창에는 `DEV 브랜치명 · 짧은해시`, 메뉴에는 같은 구분이 표시됩니다.

개발 표시의 브랜치명은 앱 시작 시 읽습니다. 브랜치를 전환하면 앱을 다시 시작해야 표시가 바뀝니다. Detached HEAD에서는 `detached@커밋해시`, Git 정보를 읽을 수 없으면 작업 폴더명을 표시합니다.

개발 CLI는 해당 워크트리의 `src-tauri/target/debug/agent-gibbon`만 사용하고, 빌드 출처를 확인합니다. release·설치본으로 대체하지 않습니다. 개발 실행기는 `CARGO_TARGET_DIR`를 해당 워크트리로 고정하며 `FLOATNOTE_INSTANCE`·`FLOATNOTE_DEV_NAME`을 자동 전달합니다. 이 변수는 직접 지정할 필요가 없습니다. 로컬 통신 호환성을 위해 내부 변수 이름은 `FLOATNOTE_`를 유지하며, 이전 `scripts/floatnote-dev`는 개발 CLI의 호환 진입점입니다. 기본 호스트 debug 빌드를 지원하며 `npm run dev -- --no-watch`로 감시를 끌 수 있습니다. 다른 프로필·타깃·runner 옵션은 지원하지 않습니다.

기존 `scripts/agent-gibbon`과 환경변수 없이 실행한 설치 앱은 기본 `/tmp/floatnote-{uid}/` 통신 경로를 유지합니다. 개발 검증에는 반드시 `scripts/agent-gibbon-dev`를 사용하세요. `close`는 해당 메모를 숨길 뿐이며, `npm run dev`의 종료는 그 실행에서 시작한 개발 앱에만 적용됩니다. CLI가 자동 시작한 앱은 개발 바이너리 경로로 프로세스를 식별해 종료하세요. 이름만으로 모든 앱을 일괄 종료하지 마세요.

메모·창 상태는 프로세스별로 독립적이지만, `--file`로 같은 원본 파일을 연결하면 파일 자체는 공유됩니다. 동시에 편집할 테스트 파일도 워크트리별로 준비하세요. 두 워크트리를 각각 빌드하고 개발 앱이 실행되지 않은 상태에서 `python3 scripts/isolation-smoke.py --peer /절대경로/다른워크트리`로 동시 실행 회귀를 확인할 수 있습니다. 기존 기본 앱은 실행 중이어야 하며 검증은 기존 앱을 종료하지 않습니다.

앱 아이콘은 `assets/icon.svg`를 바탕으로 Tauri CLI로 생성했습니다.

## CLI

```sh
./scripts/agent-gibbon open --title '구현 작업' --status '진행 중' --file examples/progress.md
./scripts/agent-gibbon update --status '검증 중'
printf '# 결과\n- [x] 구현 완료\n- [ ] 리뷰\n' | ./scripts/agent-gibbon update --file -
./scripts/agent-gibbon close
# 숨긴 상태에서 내용만 변경합니다.
./scripts/agent-gibbon update --markdown '검증이 끝났습니다.' --status '완료'
./scripts/agent-gibbon open
./scripts/agent-gibbon inspect
./scripts/agent-gibbon --help
```

여러 창은 ID로 구분합니다. ID를 생략하면 기존과 같은 기본 창 `main`을 사용합니다.

```sh
./scripts/agent-gibbon open --id research --title '자료' --color '#fff1b8' --markdown '# 조사 메모'
./scripts/agent-gibbon open --id build --title '구현' --color '#18304a' --markdown '# 구현 메모'
./scripts/agent-gibbon update --id research --color '#dcecff'
./scripts/agent-gibbon inspect --id build
./scripts/agent-gibbon close --id research
./scripts/agent-gibbon list
```

- ID는 영문·숫자·하이픈·밑줄 1~64자이며 대소문자를 구분합니다. 같은 ID의 `open`은 기존 창을 복원하고 다른 ID는 새 창을 만듭니다.
- `update`·`close`·`inspect`는 기존 ID만 받습니다. 없는 창은 오류이며 다른 창에 대신 적용하지 않습니다.
- 색상은 `open`·`update`의 `--color '#RRGGBB'`로 지정합니다. 새 노트는 이미지의 스티커 색상인 노랑 `#fee93e` → 파랑 `#89f0ff` → 초록 `#84fe83` → 분홍 `#ffb2b1` → 보라 `#9cb6ff` → 회색 `#dadada` 순으로 순환합니다. 숨긴 노트와 직접 색상을 지정한 노트를 포함한 저장된 노트 수를 기준으로 하므로 재실행 후에도 이어집니다. 기존 노트에서 생략하면 색상을 유지하며 응답은 소문자로 정규화됩니다. 빈 값·이름·알파 채널은 받지 않습니다. 이전 어두운 색상 지정은 `--color '#20252e'`입니다.
- 색상은 창 전체 배경에 적용되고 글자색은 대비가 높은 흑백으로 선택됩니다. 코드·버튼 배경도 함께 바뀝니다.
- 내용·색상·위치·크기·숨김·고정 상태는 창별로 독립적입니다. 새 창은 화면 오른쪽부터 배치하고 겹치지 않는 세로 위치를 무작위로 선택합니다. 오른쪽 열이 차면 왼쪽의 빈 열을 찾고, 현재 모니터에 공간이 없으면 다른 모니터도 확인합니다. 보이는 Agent Gibbon 창 및 화면 가장자리와 8px 간격을 확보하며, 모든 모니터에 빈 공간이 없으면 겹치는 면적이 가장 작은 화면 내 위치에 배치합니다. 숨긴 창은 공간을 점유하지 않습니다. 기존 창을 다시 열 때도 목적지를 새로 계산하고, 이미 보이는 다른 창은 이동시키지 않습니다.
- `list`는 숨긴 창을 포함해 ID순으로 `id`, `title`, `status`, `color`, `visible`, `always_on_top`을 반환합니다. 본문은 개별 `inspect`로 확인합니다.

`--title`, `--status`, `--markdown` 또는 `--file`은 `open`/`update`에서 사용합니다. 생략한 필드는 보존하며 빈 문자열은 값을 비웁니다. `--markdown`과 `--file`은 함께 쓸 수 없습니다. 요청 전체는 JSON 인코딩 후 1MiB 이하, 제목과 상태는 각각 UTF-8 1024바이트 이하입니다.

체크리스트는 각 행을 `- [ ] 항목` 또는 `- [x] 완료 항목`으로 작성합니다. 목록 기호가 빠진 `[ ] 항목`은 `MARKDOWN_TASK_MARKER` 오류로 거부합니다. JSON의 `ok: false`, `error`에 행 번호·수정 예시를 반환하고 종료 코드는 1입니다. 기존 메모의 내용·제목·색상·상태는 변경하지 않으며, 호출자는 해당 행을 수정한 뒤 같은 요청을 재시도할 수 있습니다. 코드 블록·인라인 코드·정상 링크는 허용합니다. 일반 문장 전체를 검사하는 Markdown 린터는 아닙니다.

macOS에서는 마우스 포인터가 노트 밖에 있으면 창 전체가 50% 반투명이고, 노트 위에 있으면 완전 불투명해집니다. 창 포커스·위치·고정 상태는 바꾸지 않습니다. 포인터 진입/이탈과 주기적 동기화로 드래그·재열기 이후에도 복구되며 `inspect.opacity`에서 0.5 또는 1.0을 확인할 수 있습니다.

`inspect`는 실제 창의 가시성·포커스·위치·크기·상단 고정과 현재 메모를 JSON으로 반환합니다. 좌표와 크기는 물리 픽셀입니다. 성공 응답은 네이티브 처리 완료를 뜻하며 화면은 최대 약 350ms 뒤 갱신됩니다. 갱신 시각은 Unix epoch 밀리초로 반환하며 CLI 메타데이터에만 보관합니다. 제목·상태·시각은 본문 공간을 차지하지 않으며 필요한 제목은 Markdown 본문에 작성합니다.

앱이 실행되지 않았다면 `update`, `close`, `inspect`, `list`는 실패합니다. 자동 실행은 `open`만 수행합니다. 닫기 버튼·Escape·네이티브 닫기 요청은 프로세스를 종료하지 않고 창만 숨깁니다. 숨긴 뒤에도 메모 내용을 갱신할 수 있습니다. 직접 앱 번들을 실행하는 것도 명시적인 열기로 취급합니다. 메뉴 막대의 Agent Gibbon 아이콘에서 **열린 메모 앞으로**를 선택하면 보이는 창만 앞으로 가져오며, 아래 개별 메모를 선택하면 숨긴 창도 복원합니다. 이 조작은 고정 상태와 위치를 바꾸지 않습니다.

메모는 생성·CLI 갱신·연필 저장 즉시 Markdown 파일로 보관합니다. 본문과 제목·상태·색상·원본 파일 연결·갱신 시각을 복원하며, 재실행 시 기존 메모는 숨긴 상태로 불러옵니다. 메뉴 또는 `open --id ID`로 필요한 메모를 엽니다. 위치·크기·글자 크기·핀·접힘·미저장 초안은 세션에만 유지됩니다. `close`는 숨기기이며 저장 파일을 삭제하지 않습니다. 재부팅 후 자동 실행하지 않습니다.

설치 앱은 `~/Documents/agent-gibbon/docs/<노트 ID>/index.md`에 저장합니다. 실제 문서 폴더는 [Tauri 문서 경로](https://docs.rs/tauri/latest/tauri/path/struct.PathResolver.html#method.document_dir)를 사용합니다. 개발 앱은 `~/Library/Application Support/org.egoing.floatnote/notes/dev-<워크트리 해시>/docs/<노트 ID>/index.md`로 분리합니다. `inspect.storage_path`에서 파일 절대 경로를 확인할 수 있습니다. 소문자 ID는 폴더명으로 그대로 사용하고 대문자는 `~`와 16진수로 표현합니다(예: `Ab` → `~41b`). macOS에서도 대소문자만 다른 ID가 충돌하지 않습니다.

각 노트 폴더 안의 `index.md`만 읽고 갱신합니다. 다른 파일은 그대로 보존하며 이미지 캡처·렌더링 기능은 이번 변경에 포함하지 않습니다. 문서 첫 HTML 주석은 기존 복원용 JSON 메타데이터이고 이후는 Markdown 본문 원문입니다. 날짜 추적을 위한 추가 메타데이터는 만들지 않습니다. 파일시스템의 생성일·수정일을 확인할 수 있지만, 원자적 교체·복사·복원으로 생성일이 달라질 수 있으므로 최초 노트 작성일로 보장하지 않습니다.

파일은 임시 파일 기록·동기화 후 원자적으로 교체하며 저장 실패는 CLI/편집 오류로 알립니다. 손상된 저장 파일은 덮어쓰지 않고 시작 오류로 알립니다. 이전 `notes/default/*.md` 또는 개발 인스턴스의 `*.md`는 시작 시 새 구조로 복사하며 기존 파일은 보존합니다. 새 위치에 이미 존재하는 문서는 덮어쓰지 않습니다.

저장 폴더의 파일은 앱을 종료한 상태에서 백업하거나 편집하세요. 실행 중 자동 감시는 하지 않습니다. `--file`로 연결한 원본과 앱 저장소는 별개이며, 연필 저장은 양쪽을 갱신합니다. 두 파일의 동시 교체는 단일 트랜잭션이 아니므로 도중 강제 종료 시 차이가 생길 수 있습니다. 기존 원본 충돌 검사는 유지합니다. 구버전 프로세스의 메모리는 자동 이관하지 않으므로 교체 전에 필요한 내용을 파일로 보관하세요.

## 본문 변경 알림

보이는 노트의 실제 Markdown 본문이 바뀌면 그 노트만 앞으로 올리고, 마지막 변경부터 3초 동안 완전 불투명하게 표시합니다. 키보드 포커스·위치·핀은 유지합니다. 동일 본문 재전송이나 제목·상태·색상 변경은 알림을 시작하거나 연장하지 않습니다. 자동 크기는 기존 규칙을 따르고 수동 크기는 보존합니다.

추가된 행은 녹색, 수정된 행은 호박색, 삭제된 이전 행은 붉은색 배경과 취소선으로 표시합니다. 마지막으로 확인한 본문과 현재 본문을 비교하므로 `A → B → C`로 갱신되면 `A → C`의 누적 차이가 남습니다. 중간 버전의 변경 기록을 나열하지 않으며, 기준 내용으로 되돌린 부분은 diff에서 빠집니다.

변경 표시가 있을 때 노트 하단에 ‘변경사항 · ✓ 확인’ 메뉴가 나타납니다. 메뉴는 본문 스크롤 영역과 별도 공간을 사용해 내용을 가리지 않습니다. ‘확인’을 누르면 변경 표시와 삭제된 행이 사라지고, 현재 본문이 다음 비교의 기준이 됩니다. 마우스 진입·내부 이동·포커스 변경은 diff를 지우지 않습니다. 확인은 노트별로 적용되며 3초 불투명 기한을 바꾸지 않습니다. 비교 기준도 로컬 저장 파일에 보관하므로 재실행 후 미확인 차이가 복원됩니다. 확인 저장에 실패하면 표시와 기준을 유지하고 오류를 안내합니다.

강조는 앱의 별도 안전한 렌더링 결과입니다. Markdown 원문·연결 파일·복사 내용은 바꾸지 않습니다. HTML 정리와 CSP는 그대로 적용합니다. 기본 비교는 행 LCS이며 큰 본문은 계산량을 제한하는 순서 기반 비교를 사용하므로 이동된 행을 변경으로 표시할 수 있습니다.

숨기면 불투명 타이머만 끝내고 미확인 강조는 유지합니다. 숨긴 상태의 갱신은 창을 열지 않으며 마지막 확인 기준으로 누적 차이를 갱신합니다. 재열기에서는 미확인 강조가 남아 있고, 이동은 기존 등장 효과를 사용합니다. 최초 표시는 변경 강조를 만들지 않습니다. 등장·워프 중 갱신도 마지막 실제 변경의 기한을 사용하며, 등장 이동이 진행 중이면 기존 등장 불투명 규칙이 우선합니다. 편집 중에도 초안과 충돌 검사를 보존하며 강조 표시만 숨겨진 본문에 반영합니다. 버튼 확인은 현재 화면에 표시된 변경 버전만 해제하므로, 늦게 도착한 확인 요청이 다음 변경의 강조를 지우지 않습니다. 네이티브 불투명 복귀는 별도 기한 타이머로 처리합니다.

## 로컬 통신과 안전한 렌더링

동일 사용자 전용 `/tmp/floatnote-<uid>/` 디렉터리(0700)의 Unix socket으로 요청을 전달합니다. 파일 잠금으로 중복 앱을 막고, 잠금을 획득한 프로세스만 이전 socket을 정리합니다. 별도 HTTP 서버나 포트는 없습니다. 같은 사용자 계정의 다른 프로세스는 CLI와 동일한 권한으로 메모에 접근할 수 있습니다. 모든 메모를 로컬 Markdown 저장소에 보관하며, 연필 편집에서는 연결된 `--file` 원본도 갱신합니다.

Rust에서 Markdown을 HTML로 변환하고 정리한 뒤 WebView에 전달합니다. HTML 입력을 실행하지 않으며 체크리스트는 ☑/☐로 표시합니다. 이미지와 링크 이동은 지원하지 않습니다. CSP와 최소 창 조작 권한을 적용했습니다.

## 에이전트용 사용 스킬

[Agent Gibbon 사용 스킬](.agents/skills/agent-gibbon/SKILL.md)은 설치된 macOS 앱의 실행 경로와 메모 생성·조회·갱신·색상 지정·숨김 보존 규칙을 담고 있습니다. 앱 소스나 개발 빌드 없이 사용할 수 있으며, 개발 실행 절차는 위의 빌드와 실행 절을 따릅니다. 작업계획 표시 같은 운영 정책은 사용자 `AGENTS.md`에서 정합니다. 예제는 [examples/progress.md](examples/progress.md)입니다.

## 검증

```sh
npm test
npm run check
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
node --check ui/app.js
python3 scripts/smoke.py
python3 scripts/multiwindow-smoke.py
python3 scripts/markdown-validation-smoke.py
# 개발 앱이 종료된 상태에서, 현재 워크트리의 개발 빌드만 재시작
npm run dev:build
python3 scripts/persistence-smoke.py
# macOS에서 마우스를 조작하지 않은 상태로 네 방향·드래그·접기 회귀
python3 scripts/entrance-direction-smoke.py
# macOS 자동화/손쉬운 사용 권한이 있는 환경에서 UI 버튼 검증
python3 scripts/editor-ui-smoke.py
python3 scripts/macos-ui-smoke.py
python3 scripts/multiwindow-ui-smoke.py
python3 scripts/macos-tray-smoke.py
```

`multiwindow-smoke.py`는 별도 ID의 창 두 개로 독립 상태·색상·목록·잘못된 IPC·기본 창 호환성을 검사하고 테스트 창만 숨깁니다.

`smoke.py`는 실제 앱을 실행하거나 기존 앱의 메모를 교체하고 마지막에 숨깁니다. 포커스·위치·크기 보존, 반복 갱신, 닫은 뒤 갱신, 다시 열기, JSON 오류, 한글 체크리스트와 위험한 HTML 차단을 검사합니다. 실행 중 메모와 사용자 입력을 동시에 조작하지 마세요. `macos-ui-smoke.py`는 실제 WebView의 한글·체크리스트와 핀/숨기기 버튼을 macOS 접근성 API로 검증합니다. `multiwindow-ui-smoke.py`는 두 창의 본문과 고정/숨기기 버튼이 해당 창에만 적용되는지 확인합니다. `macos-tray-smoke.py`는 실제 메뉴 막대 아이콘으로 개별 숨긴 메모 복원과 열린 메모 앞으로 기능을 확인합니다. UI 스크립트는 macOS CLT의 Swift와 접근성 권한이 필요합니다. 화면 잠금을 해제하고 다른 앱에 포커스를 둔 상태에서 실행하세요. 본문 전체 드래그와 가장자리 크기 조절도 확인합니다.

환경과 수행 결과는 [검증 기록](docs/verification.md)에 기록합니다.

## 배포판 제작과 설치

버전은 `npm run version:set -- X.Y.Z`로 npm·Cargo·Tauri와 lockfile을 함께 갱신하고 `npm run version:check`로 확인합니다. 해당 커밋의 `vX.Y.Z` 태그를 push하면 macOS Apple Silicon·Intel DMG와 Windows x64 설치 EXE를 자동 빌드합니다. 세 플랫폼 모두 테스트·Rustfmt·Clippy·빌드에 성공한 뒤 설치 파일 세 개와 `SHA256SUMS.txt`를 Draft에 업로드하고 공개합니다. 기존 공개 파일은 덮어쓰지 않습니다.

일반 브랜치 push와 수동 실행은 검증·빌드만 수행합니다. Rust 의존성 캐시는 GitHub Actions에 저장하며, 앱·설치 파일은 다시 빌드하고 테스트도 유지합니다. 캐시를 소스 저장소에 커밋하지 않습니다. 배포용 Sentry DSN 설정과 서명 제한, 실패 시 처리 등 상세 절차는 [자동 릴리스 안내](docs/releases.md)를 참고하세요.

설치 파일은 [GitHub Releases](https://github.com/egoing/agent-gibbon/releases)에서 받습니다. 공개 저장소에서 다운로드할 수 있습니다.

```sh
npm run build:release
```

호스트 CPU용 앱과 DMG를 `src-tauri/target/release/bundle/`에 만듭니다. v0.2.7은 Apple Silicon용 `Agent Gibbon_0.2.7_aarch64.dmg`와 Intel용 `Agent Gibbon_0.2.7_x64.dmg`를 제공합니다.

새 빌드의 **Agent Gibbon.app을 Applications로 복사**한 후 실행합니다. 기존 v0.2.5 이하 릴리스 자산은 당시 이름인 Floatnote를 유지합니다. 이 배포판은 Apple Developer ID 서명·공증을 하지 않았습니다. 신뢰하는 출처에서 받은 파일인지 확인한 후 macOS의 **시스템 설정 → 개인정보 보호 및 보안 → 그래도 열기** 절차가 필요할 수 있습니다.

설치된 앱에 포함된 CLI도 사용할 수 있습니다.

```sh
'/Applications/Agent Gibbon.app/Contents/MacOS/agent-gibbon' open --markdown '# 안녕하세요'
```

새 버전으로 교체하기 전 필요한 메모를 저장하고 실행 중인 앱을 종료하세요. 새 버전의 저장된 메모는 재실행 시 복원되며 창 배치 설정은 초기화됩니다.

커서 옆 대기와 등장 이동 중에는 창을 완전 불투명하게 표시하고, 도착 후 기존 포인터 기반 반투명 동작을 적용합니다. 표시 후 첫 1초 동안은 마우스가 움직여도 자동 이동하지 않습니다. 그동안 8 논리 px 임계값을 넘은 첫 방향을 기억했다가 1초가 지나면 실행합니다. 좌우는 해당 가장자리로, 위는 접어서 오른쪽으로 이동하며 아래는 현재 위치에서 숨깁니다. 마우스가 그대로 있으면 시간 제한 없이 대기합니다. CLI `open`은 표시 준비만 기다리고 반환하며 마우스 이동을 기다리지 않습니다. 응답의 `animating: true`는 대기 또는 이동 중이라는 뜻입니다.

커서가 화면 오른쪽 아래에 있으면 노트는 왼쪽 위를 우선합니다. 화면 작업 영역 안으로 보정한 뒤에도 커서를 가리지 않는지 검사하고, 음수 좌표와 서로 다른 화면 배율을 고려합니다. 창이 너무 크거나 커서 주변에 안전한 공간이 없으면 크기를 보존하고 기존 배치 목적지에 바로 표시합니다. 직접 드래그하면 자동 이동을 취소하며, 닫기 버튼·CLI로 대기 중 숨기면 목적지를 보존합니다(아래 방향 제스처는 현재 위치에서 숨깁니다). 대기 중 내용 변경에 따른 자동 크기는 이동이 끝난 뒤 반영됩니다.

## 내용에 맞춘 자동 크기

새 패널은 내용을 측정한 크기로 커서 옆에서 등장합니다. 내용·글자 크기가 바뀌면 가로 300 고정, 세로 48~420 논리 픽셀 범위에서 다시 맞추며, 최대 높이를 넘는 본문은 스크롤합니다. 화면이 작으면 작업 영역 안으로 자동 크기를 제한합니다.

사용자가 가장자리를 드래그하면 해당 창은 앱을 종료할 때까지 수동 크기를 유지합니다. 이후 내용 갱신이나 숨김·복원으로 자동 크기를 덮어쓰지 않습니다. 수동 조절은 자동 범위 밖으로도 가능하며, 조작 버튼을 위한 하한 144×32 논리 픽셀만 적용하고 최대 크기는 제한하지 않습니다. 사용자가 크게 만든 공간은 그대로 유지합니다.

## Sentry 오류 수집

[Sentry Rust SDK](https://docs.sentry.io/platforms/rust/)로 앱 프로세스의 Rust panic과 WebView의 처리되지 않은 오류·Promise rejection을 수집합니다. 네이티브 크래시 덤프, 정상적으로 처리한 CLI/편집 오류, 성능 추적과 세션 리플레이는 수집하지 않습니다.

오류 수집은 **release 빌드에 유효한 `AGENT_GIBBON_SENTRY_DSN`을 빌드 시 주입한 경우에만** 켜집니다. 개발(debug)·테스트 빌드는 DSN이 있어도 SDK를 초기화하지 않습니다. 일반 소스 빌드에는 기본 DSN이 없으며, 실행 환경의 `SENTRY_DSN`이나 과거 `FLOATNOTE_SENTRY_DSN`으로 켤 수 없습니다.

공식 배포 담당자는 배포 환경에서 공개 수신용 DSN을 주입한 뒤 빌드합니다. 관리용 인증 토큰을 넣으면 안 됩니다. `.env`는 자동 로드하지 않습니다.

```sh
# 배포 환경에서 AGENT_GIBBON_SENTRY_DSN을 주입한 뒤 실행
npm run build:release
```

주입된 DSN은 앱에 포함되므로 사용자의 추가 설정 없이 Finder 실행에도 적용됩니다. DSN을 생략하거나 빈 값·잘못된 값을 주입한 빌드는 수집하지 않습니다. 실행 시 DSN을 바꾸는 기능은 지원하지 않습니다. 공식 배포 전 빌드 환경의 DSN 설정을 확인하세요. 이 정책은 이 변경 이후 빌드부터 적용되며, 이미 배포한 v0.2.7 이하 설치 파일의 동작은 바뀌지 않습니다. `environment: production`은 분류용이며, 실제 전송 허용 여부는 위 빌드 조건으로 결정합니다.

메모 본문·제목·상태·연결 파일 경로·CLI 인수는 오류 수집에 전달하지 않습니다. Rust panic 메시지와 소스 문맥은 전송 전에 제거하고 WebView는 오류 종류만 고정 문구로 전달합니다. WebView 보고는 프로세스당 20건으로 제한합니다. 릴리스 버전, 실행 환경, SDK가 제공하는 OS/런타임 정보와 Rust 스택 정보는 진단에 사용됩니다. 서버는 네트워크 연결의 IP 주소를 볼 수 있습니다.

자동 테스트는 네트워크 전송 없이 개발·테스트 차단과 release DSN 조건 및 개인정보 제거를 검증합니다. 실제 수신 확인은 DSN을 주입한 공식 release 앱에서 별도로 수행해야 합니다. 기존 `live_sentry_delivery` 테스트는 테스트 빌드 수집 금지 정책에 따라 제거했습니다.

## Agent Gibbon 이름 전환

앱 표시 이름은 **Agent Gibbon**, 저장소·CLI·스킬 이름은 `agent-gibbon`입니다. 기존 `scripts/floatnote`는 새 CLI로 연결하는 호환 진입점입니다.

기존 메모와 설정을 보존하기 위해 앱 식별자 `org.egoing.floatnote`, Unix socket 디렉터리 `/tmp/floatnote-<uid>`, 안내 숨김 설정 키는 유지합니다. 실행 중인 Floatnote에도 새 CLI로 접근할 수 있습니다. 설치 파일을 교체해도 실행 중인 앱은 자동 종료하지 않으며, 새 표시 이름과 기능은 다음 앱 시작부터 적용됩니다. 구버전의 메모리는 복원되지 않으므로 교체 전 필요한 내용을 먼저 저장하세요.

Sentry DSN은 빌드 시 `AGENT_GIBBON_SENTRY_DSN`만 사용합니다. 기존 `FLOATNOTE_SENTRY_DSN` 호환과 실행 시 DSN 재지정은 지원하지 않습니다. 과거 검증 로그·릴리스 이름과 Sentry 프로젝트 이름은 이전 기록과의 연결을 위해 보존합니다.
