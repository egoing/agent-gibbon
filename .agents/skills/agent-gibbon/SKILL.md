# Agent Gibbon 사용

저장소 루트의 `scripts/agent-gibbon`을 사용한다. 설치 앱은 `"/Applications/Agent Gibbon.app/Contents/MacOS/agent-gibbon"`으로도 호출할 수 있다. 다른 디렉터리에서는 절대 경로로 호출한다. 실행 파일이 없으면 README의 빌드 절차를 수행한다. 셸 인수는 안전하게 인용하고, 긴 Markdown은 파일 또는 표준입력으로 전달한다.

```sh
./scripts/agent-gibbon list
./scripts/agent-gibbon open --id my-note --title '메모' --color '#fff1b8' --file examples/progress.md
./scripts/agent-gibbon update --id my-note --status '갱신됨' --file examples/progress.md
./scripts/agent-gibbon update --id my-note --color '#dcecff'
./scripts/agent-gibbon inspect --id my-note
./scripts/agent-gibbon close --id my-note
```

- `--id`는 영문·숫자·하이픈·밑줄 1~64자이며 대소문자를 구분한다. 생략하면 기본 창 `main`을 대상으로 한다. 같은 ID는 같은 창을 재사용하고 다른 ID는 별도 창을 만든다.
- `list`는 숨긴 창까지 ID순으로 제목·상태·색상·가시성·상단 고정을 반환한다. 본문은 `inspect --id ID`로 조회한다.
- `--color '#RRGGBB'`는 창 전체 배경색이다. 글자색은 자동 선택된다. 기본색은 `#20252e`, 생략하면 보존한다. 빈 문자열·색상 이름·알파값은 허용하지 않는다.
- 최초 표시와 사용자의 명시적인 복원 요청에만 `open`을 사용한다. `open`은 필요하면 앱과 해당 창을 생성한다. 없는 ID에 대한 `update`·`close`·`inspect`는 실패한다.
- 새 창과 숨긴 창을 열면 커서가 있는 모니터에서 커서를 가리지 않는 가까운 위치에 12 논리 px 여백을 두고 완전 불투명하게 대기한다. 표시 후 첫 1초는 마우스가 움직여도 자동 이동하지 않고, 그동안 이동이 감지됐다면 1초가 지난 뒤 기존 배치 목적지까지 420ms cubic ease-out으로 이동한다. 마우스를 움직이지 않았다면 계속 기다리다가 이동이 감지되면 출발한다. 이미 보이는 창에는 반복하지 않는다. CLI `open`은 표시 준비만 기다리고 반환하며 마우스 이동을 기다리지 않는다. 응답의 `animating: true`는 대기 또는 이동 중을 뜻한다. 화면 경계·음수 좌표·화면 배율을 고려하며, 크기를 유지한 채 안전한 공간을 확보할 수 없으면 목적지에 바로 표시한다. 이동 중 직접 드래그하면 자동 이동을 중단하고, 숨기면 원래 목적지를 보존한다.
- 새 창은 화면 오른쪽부터 배치하고 겹치지 않는 세로 위치를 무작위로 선택한다. 오른쪽 열이 차면 왼쪽 빈 열을 찾는다. 보이는 Agent Gibbon 창과 화면 가장자리를 피해 8px 간격을 유지한다. 현재 모니터에 공간이 없으면 다른 모니터를 확인하고, 모든 모니터가 부족하면 겹치는 면적이 가장 작은 위치를 사용한다. 숨긴 창은 배치 장애물에서 제외하며 기존 창을 복원할 때도 다른 창과 이동 중인 창의 목적지를 피해서 배치를 다시 계산한다.
- 제목·상태·갱신 시각은 CLI 메타데이터이고 화면에는 본문과 aA·연필·복사·워프·핀·닫기 버튼을 표시한다. 화면에 필요한 제목·상태는 Markdown 본문에 넣는다. 체크박스 행은 목록 점·들여쓰기 없이 표시된다.
- 진행 변경은 `update`로 보낸다. 숨긴 창은 그대로 숨겨진 채 내용만 갱신된다. 갱신 실패를 `open`으로 자동 대체하지 않는다.
- 생략한 제목·본문·상태는 기존 값을 유지한다. 이 세 필드의 빈 문자열은 해당 필드를 비운다. 창별 내용·색상·위치·크기·숨김·상단 고정은 서로 독립적이다.
- 사용자는 메뉴 막대의 Agent Gibbon 아이콘에서 `열린 메모 앞으로` 또는 개별 메모를 선택해 창을 복원할 수 있다. 열린 메모 앞으로는 숨긴 창을 열지 않으며, 개별 선택은 해당 창만 명시적으로 복원한다.
- 메뉴 막대의 개별 메모 왼쪽 ✓는 현재 열린 창을 뜻합니다. 숨긴 창에는 체크가 없고, 접힌 창은 열린 창으로 표시합니다. 항목을 선택하면 기존처럼 해당 메모를 앞으로 가져오거나 복원하며, 체크된 항목을 다시 선택해도 숨기지 않습니다.
- `close`는 숨기기다. 프로세스가 유지되어 이후 갱신을 받을 수 있다.
- 종료 코드와 JSON의 `ok`를 확인한다. `inspect`로 가시성·위치·크기·포커스·상단 고정과 내용을 읽을 수 있다. 메모 원문이나 민감한 내용을 외부로 전송하지 않는다.
- 창 전체를 드래그해 이동한다. 버튼·편집 영역·크기 조절 가장자리는 제외한다. 본문은 선택 대신 복사 버튼으로 전체 텍스트를 클립보드에 복사할 수 있다.
- 렌더링된 체크리스트는 읽기 전용이며 연필 버튼으로 Markdown 원문을 편집할 수 있다. 사용자 답변, 기존 창 자동 재배치, 클라우드는 지원하지 않는다.
- 프로세스를 종료하면 모든 메모·색상·창 위치는 초기화된다. `close`는 창을 삭제하지 않으며 숨긴 창도 프로세스 메모리에 남는다. 갱신은 위치를 보존하며 숨긴 창을 다시 열 때는 겹침을 줄이도록 목적지를 다시 계산한다. 자동 크기는 내용에 맞춰 바뀌지만 수동 크기는 유지한다.

실제 사용 예제: 저장소의 `examples/progress.md`.

표시할 내용과 갱신 시점은 사용자 또는 호출한 워크플로우가 정한다. 이 스킬은 작업계획 작성이나 완료 체크를 강제하지 않는다.

## Markdown 검증과 재시도

체크리스트는 각 줄에 `- [ ] 대기 항목`, `- [x] 완료 항목`으로 작성한다. 화면에서 목록 점을 숨겨도 원문의 `-`는 필요하다. `[ ] 항목`만 쓰면 일반 문단이 되어 줄바꿈과 체크박스가 사라진다.

`MARKDOWN_TASK_MARKER` 오류는 잘못된 행 번호와 수정 방법을 반환하며 종료 코드는 1이다. 기존 메모는 그대로 유지된다. 해당 행을 수정하고 같은 ID로 원래 요청을 다시 보낸다. 성공(`ok: true`)을 확인하며, 같은 오류가 반복되면 무한 재시도하지 말고 원문과 오류를 확인한다. 코드 블록·인라인 코드·정상 링크는 검사에서 제외한다. 문자 그대로의 `[ ]`는 인라인 코드 또는 `\[`로 이스케이프한다. 모든 Markdown 오류를 검사하는 기능은 아니다.

macOS에서는 포인터가 노트 밖에 있으면 창 전체가 50% 반투명이고, 노트 위에 있으면 완전 불투명하다. 포커스나 고정 상태는 바꾸지 않는다.

## 글자 크기와 원문 편집

- `aA`는 창별 글자 크기를 12·14·16·18px로 순환한다. CLI 갱신·숨기기 후에도 유지되며 앱 종료 시 초기화된다.
- 연필로 Markdown 원문을 편집한다. 저장 버튼 또는 ⌘S/Ctrl+S로 저장하고 취소/Escape로 편집을 취소한다. 숨기면 초안은 유지된다.
- `--file 경로`는 원본 파일의 절대 경로를 연결한다. 연필 저장 시 메모와 파일을 함께 갱신한다. `--markdown`·`--file -`는 메모만 수정하며 본문 교체 시 이전 파일 연결을 해제한다. 제목·상태·색상만 갱신하면 연결을 유지한다.
- 편집 중 CLI 갱신이나 외부 파일 변경이 있으면 저장을 거부하고 초안을 남긴다. 필요한 내용을 복사하고 최신 내용으로 다시 편집한다. 외부 파일 변경은 `update --id ID --file 경로`로 다시 읽는다. 파일 자동 감시는 하지 않는다.
- `inspect.note.markdown`은 현재 원문이고 `inspect.note.source_path`는 연결된 파일 경로 또는 null이다. 다른 도구로 원본 파일을 동시에 쓰지 않는다.

## 워프

- 좌우 화살표 버튼 또는 macOS Alt(⌥ Option) + 포인터 접촉으로 현재 모니터 반대편 가장자리로 이동한다. 처음 열린 세로 위치를 기준으로 화면 안에 배치하며, 크기·초안·고정·포커스는 유지한다. 다른 메모와 겹칠 수 있다.
- 이동 직후 자동 반복하지 않는다. 포인터를 밖으로 움직였다가 다시 접촉하거나 Alt를 놓았다가 다시 누르면 재실행한다. 숨긴 메모에는 동작하지 않는다.
- 단축키 안내는 노트 하단에 12초 표시한다. ‘다시 보지 않기’ 설정은 모든 노트와 앱 재실행에 걸쳐 유지된다.

커서 옆 대기와 등장 이동 중에는 창을 완전 불투명하게 표시하고, 도착 후 기존 포인터 기반 반투명 동작을 적용합니다. 대기 중 내용 변경에 따른 자동 크기는 이동이 끝난 뒤 반영됩니다.

## 자동 크기와 수동 조절

- 새 패널은 내용을 먼저 측정한 뒤 표시한다. 자동 크기는 가로 300 고정, 세로 48~420 논리 픽셀이며 화면 작업 영역을 넘지 않도록 제한한다. 긴 내용은 스크롤한다.
- 내용·글자 크기 변경 시 자동 크기를 다시 계산한다. 가장자리 드래그 후에는 그 창의 자동 크기 조절을 멈추고 사용자가 지정한 크기를 앱 종료까지 유지한다.
- 수동 크기는 자동 최소·최대를 벗어날 수 있다. 버튼 조작을 위한 144×32 논리 픽셀 하한만 유지하고 최대 제한은 없다.

## 본문 변경 알림

보이는 노트의 실제 본문 갱신은 포커스·위치·핀을 유지하며 앞으로 올리고 마지막 변경부터 3초 동안 완전 불투명하게 표시한다. 동일 본문·메타데이터만의 갱신은 효과를 시작/연장하지 않는다. 숨긴 노트는 그대로 숨김을 유지하며 숨길 때 불투명 타이머만 종료한다.

앱은 변경 행을 커서가 노트에 진입하거나 내부에서 움직일 때까지 강조한다. 다음 실제 본문 변경에는 이전 강조를 새 변경으로 교체한다. 커서 확인은 3초 불투명 기한을 줄이지 않으며 숨김·복원에도 미확인 강조를 보존한다. 앱이 강조를 처리하므로 호출자는 강조용 Markdown을 삽입하지 않는다. 원문·연결 파일·복사는 유지된다. 추가는 녹색, 수정은 호박색, 삭제된 이전 행은 붉은색 배경과 취소선으로 구분한다. 별도 삭제 안내는 없으며, 비활성 창에서도 마우스가 닿으면 삭제된 행과 변경 표시를 제거하고 최종 본문으로 전환한다. 빈 본문도 처리한다. 최초 표시·재열기는 기존 등장 효과를 사용한다.

## 접기와 펼치기

- macOS Control + 포인터 접촉으로 창별 접기·펼치기를 전환한다. 다른 앱에 포커스가 있어도 동작하며, Control을 놓거나 포인터를 밖으로 움직였다가 재접촉하면 다시 전환한다.
- 접힌 상태는 높이 12 논리 px이며 10px의 작은 제목과 오른쪽 펼치기 버튼만 표시한다. 버튼으로도 펼칠 수 있다. 펼치면 이전 크기를 복원하며 본문·편집 초안·수동 크기·위치·핀을 보존한다.
- 내용 갱신은 접힌 상태를 유지한다. `inspect.folded`로 확인할 수 있다. 접힌 동안 가장자리 크기 조절은 비활성화된다.

접힌 메모는 포인터가 밖에 있을 때 불투명도 80%로 표시하여 펼친 메모(50%)보다 선명하게 유지한다. 포인터를 올리거나 변경 알림이 진행 중이면 100%로 표시한다.

펼친 상태에는 접기 아이콘, 접힌 상태에는 펼치기 아이콘을 표시한다. 아이콘에 포인터를 올리면 Control + 포인터 접촉으로 접기·펼치기를 전환하는 단축키 안내가 툴팁으로 표시된다.

## 워크트리 개발 실행

- 설치 앱·일반 실행에는 위의 `scripts/agent-gibbon`를 사용한다. 개발 테스트에는 `npm run dev:build` 후 `scripts/agent-gibbon-dev`를 사용하거나 `npm run dev`로 개발 앱을 실행한다. `npm run dev -- --no-watch`는 Rust 변경 감시를 끈다.
- 두 개발 진입점은 워크트리의 실제 절대 경로 해시로 같은 인스턴스를 선택한다. `npm run dev:info`로 ID와 바이너리 경로를 확인한다. 호출 위치가 달라도 해당 스크립트의 워크트리를 사용한다.
- 개발 CLI는 해당 워크트리에서 빌드한 debug 바이너리만 사용한다. 없거나 빌드 출처가 다르면 오류를 반환하므로 `npm run dev:build`로 빌드한다. release 또는 설치 앱으로 자동 대체하지 않는다.
- 개발 창·메뉴에는 `DEV 워크트리이름 · 짧은해시`가 표시된다. 같은 메모 ID라도 다른 워크트리와 설치 앱의 내용·숨김·수정에는 영향을 주지 않는다. `close`는 프로세스 종료가 아니라 메모 숨기기다.
- `--file`에 같은 파일을 지정하면 파일 자체는 공유되므로 개발 테스트 파일도 분리한다. 일반 설치 앱의 기본 통신 경로는 유지된다. 인스턴스 환경변수는 개발 실행기가 설정하므로 직접 지정할 필요가 없다.

## 접촉으로 닫기

macOS에서 Control + Option(Alt) + Command(Win)을 누른 채 포인터를 노트에 올리면 숨긴다. 워프·접기보다 우선하며, 접힌 노트와 비활성 창에서도 동작한다. 기존 닫기처럼 본문·편집 초안을 유지한다.
