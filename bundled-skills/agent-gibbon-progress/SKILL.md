# 작업 진행 표시

여러 단계의 실행 작업을 화면 위에서 따라볼 수 있게 한다. 이 스킬의 활성화 자체는 작업을 시작하거나 메모를 만들지 않는다. 실제 작업을 진행할 때 사용자의 표시·무표시 요청을 따른다.

## 앱 선택

macOS 설치 앱은 `/Applications/Agent Gibbon.app/Contents/MacOS/agent-gibbon`이다. 실행 가능 여부를 먼저 확인한다. Windows에서는 사용자가 설치한 `agent-gibbon.exe`의 실제 경로를 확인한다. 앱이 없으면 본 작업을 계속하며 메모만 생략한다. 앱 설치·소스 빌드는 별도 요청이 있을 때 한다.

특정 워크트리의 개발 앱을 지정했거나 Agent Gibbon을 개발·검증하는 작업에서는 해당 워크트리의 `scripts/agent-gibbon-dev`를 사용한다. 다른 개발 인스턴스나 설치 앱으로 바꾸지 않는다. 명령 옵션은 실제 `--help`로 확인한다.

## 한 작업에 한 메모

1. `list`로 기존 메모를 확인하고 충돌하지 않는 영문·숫자·하이픈·밑줄 ID(1~64자)를 정한다. 다른 작업의 메모를 덮어쓰지 않는다.
2. 검증할 수 있는 단계로 `- [ ]` Markdown 체크리스트를 만들고 `open --id ID --file -`의 표준입력으로 보낸다. 제목과 현재 상태는 본문에 쓴다. 색상은 사용자 지정이 없으면 생략한다.
3. 실제로 완료를 확인한 항목만 `- [x]`로 바꾼다. 구현과 실행 검증을 구별하고, 실패·미검증·보류 사유를 같은 메모에 적는다.
4. 이후에는 같은 ID의 `update --file -`를 쓴다. 사용자가 숨긴 창을 `open`으로 다시 띄우지 않는다. 위치·포커스·숨김 상태를 유지한다.
5. 큰 목표·단계·순서·검증 방법이 유지되면 기존 제목·문구·순서를 가능한 한 보존하고 체크 상태와 짧은 결과만 바꾼다. 단순 완료 체크는 `update --change-mode replace --highlight newly-completed --file -`를 사용한다. 중요한 본문·계획 변경은 `--change-mode diff`를 사용한다. CLI 도움말에서 옵션 지원을 확인한다. 앱이 이전 강조 해제와 이번 완료 판별을 담당하므로 표시용 Markdown이나 별도 초기화 요청을 만들지 않는다. 조용한 교체가 미확인 diff와 충돌하면 실패 사유를 남기고 중요한 변경을 diff로 갱신하며 임의로 읽음 처리하지 않는다.
6. 계획이 바뀌면 새 근거에 맞춰 갱신하며 아직 필요한 단계와 미완료 범위를 잃지 않는다. 세션을 이어받았으면 `inspect --id ID`로 현재 본문을 확인한다.
7. 작업이 끝나면 핵심 결과·완료·미완료를 남긴다. 메모를 자동으로 삭제하거나 숨기지 않는다.

CLI의 종료 코드와 JSON `ok`를 확인한다. 실패한 갱신을 성공으로 표시하지 않고 본 작업은 계속한다. 체크리스트는 목록 기호를 포함한다. 긴 내용은 인용한 heredoc 또는 파일로 보내 셸이 원문의 백틱·달러 기호를 실행하지 않게 한다.

```sh
"/Applications/Agent Gibbon.app/Contents/MacOS/agent-gibbon" open --id project-progress --file - <<'MD'
# 현재 작업
- [ ] 구현
- [ ] 실행 검증
MD
```

메모 본문은 로컬 앱에만 전달한다. 이 스킬은 음성, 외부 알림, 클라우드 전송을 추가하지 않는다.
